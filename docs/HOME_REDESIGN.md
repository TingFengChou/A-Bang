舊首頁是入口網站：要先知道自己要點哪一類。新首頁打開就回答「我現在該做什麼」，並把每個功能放在找得到的地方。

## 3. 建議卡的情境與優先序

由 `core/home-suggest.js`（第 1 期新增，純函式，前端以 `/core/home-suggest.js` 共用）決定。**輸入只有 `ContextSnapshot`（§4），輸出是決策＋用到的訊號**。規則互斥，由上往下第一個成立的就是答案：

| 序 | 情境 | 條件（全部成立） | 主按鈕 |
|---|---|---|---|
| 1 | 安全 | 地震速報、颱風停班停課（待 NCDR）、空品紅色以上 | 看詳細與求助電話 |
| 2 | 進行中 | 有進行中的行程（trip-bar） | 回到行程 |
| 3 | 新手 | 沒完成引導、沒設住家 | 三步設定 |
| 4 | 今日通勤 | 上班日、06:00–10:00、有固定通勤方式、還沒到公司 | 開始出門倒數 |
| 5 | 今日返家 | 上班日、16:30–21:00、有固定通勤方式 | 開始返家導引 |
| 6 | 末班車 | 22:30 以後、不在住家附近（或不知道位置） | 查詢末班車與返家路線 |
| 7 | 返家路線 | 週末或假日 18:00 以後、不在住家附近 | 查詢返家路線與班次 |
| 8 | 散步建議 | 符合 `core/health-nudge.js` 規則（ADR-0018） | 看散步地點 |
| 9 | 明日提醒 | 20:00 以後、明天下雨或垃圾車 | 設定提醒 |
| 10 | 一般 | 其他 | 依時段的「您可能想問」第一題 |

- 「班次異常」不是獨立情境，是今日通勤／今日返家的**狀態**（§9）。
- 「其他建議」＝ 2～10 中其他也成立的情境，最多 5 個，同一個面板。

## 4. `ContextSnapshot` 契約

```js
/**
 * @typedef {object} ContextSnapshot
 * @property {string} now            ISO 時間（台灣時間由函式內換算）
 * @property {{kind:'workday'|'makeup'|'weekend'|'holiday', name?:string}} day
 * @property {{auto: null|{lat:number,lon:number,area:string,at:string}, override: null|'fixed'|'here'}} location
 *           auto＝打開 App 時讀到的一次位置（沒允許就是 null）；override＝使用者按了出發地切換
 * @property {{home?:Place, office?:Place}} places      只存在手機
 * @property {null|Commute} commute                       固定通勤方式（§8）
 * @property {{weather?:object, aqi?:object, quake?:object}} env
 * @property {{bus?:Arrival[], metro?:Timetable[], bike?:object}} transit  沒查到是 null，不是空陣列
 * @property {{onboarded:boolean, trip:null|object, health:null|object, last:null|{q:string,at:string}}} user
 * @property {{offline:boolean, demo:boolean, quotaOut:boolean}} source
 */
```

回傳：

```js
{ kind, title, status: 'ok'|'warn'|'unknown', origin: {mode:'fixed'|'here', label, auto:boolean},
  route: [...], readout: {...}, cta: {label, action, steps:[...]}, alt: [...],
  signals: [{key:'now'|'here'|'home'|'office'|'line', label, value, tone}],  // 頭腦與核心連線只畫這些
  reasons: ['上班日', '07:40', '已設定固定通勤方式', ...] }                    // 「為何顯示此建議」
```

- `location.override` 永遠比 `location.auto` 優先；切換只影響這次畫面，不改存的資料。
- 判斷「在不在固定地點附近」：與固定地點距離 > 800 公尺就算不在（可調，寫在常數）。
- 函式不得讀時鐘、不得呼叫網路；測試用 `npm run test:clock` 的五個時段跑。

## 6. 出發地切換

- 位置：路線列的第一格，〔固定地點｜目前位置〕兩段式按鈕，高 36px；下面一行小字說明起點（「出發地・內湖區」或「信義區松仁路附近」）。
- 已允許定位：打開 App 讀一次；不在固定地點附近 → 預設選「目前位置」，眉標加橘字「已依目前位置調整」。
- 沒允許定位：預設固定地點；按「目前位置」時浮出「將取得一次目前位置，僅用於本次計算」2.5 秒，才向系統要權限。
- 沒有固定地點的情境（返家路線、末班車）：起點預設「目前位置」，小字「按下後才取得」。
- 定位失敗沿用 `js/location-help.js` 說原因，並退回固定地點。

## 7. 「您可能想問」

來源依序合併、去重，最多 5 個：

1. 接續上次（上次問的問題，24 小時內；只有文字，按了才送）。
2. 這次建議的追問（例：通勤 → 「今天需要帶傘嗎？」「文湖線有延誤嗎？」）。
3. 現在的資料觸發（下雨機率 ≥ 50%、空品橘色以上、垃圾車 1 小時內）。
4. 時段預設題（沿用 `core/agent` 的 `homeAsks`）。
5. 可疑情境（剛從簡訊或剪貼簿回來不在範圍內；只在使用者按過防詐時加「這則簡訊是詐騙嗎？」）。

## 8. 固定通勤方式

- 建立：查完路線的結果卡多一顆「設為固定通勤方式」；存的時候自動推導反向路線與預設時段（上班日 07:00–09:30 去、17:30–20:00 回），一次確認建好兩趟（共同決議 B）。
- 存在手機（`abang.commute`），可在個人頁與「為何顯示此建議」頁清除。
- 快速設定住家：晚上沒設住家時提示「您現在在家嗎？」；按了先顯示逆地理確認「設為：○○區○○附近」，可改成輸入地址或站名，才存（共同決議 5）。

## 9. 班次狀態的寫法（資料誠實）

| 資料 | 顯示 |
|---|---|
| 公車即時到站 | 「N 分」「下一班 N 分」；綠點＝即時 |
| 捷運 | 一律「依時刻表」，不畫即時綠點 |
| 下一班明顯比班距長 | 只在拿得到該時段班距、且 N > 班距 × 1.5 時：「307 班次間隔較長」＋建議改搭；否則只寫「下一班 N 分」 |
| 延誤幾分 | 不寫（TDX 不給延誤分鐘） |
| 查不到、額度用完 | 「這次查不到班次」，不寫「沒有班次」 |
| 示範資料、離線 | 眉標標示 |

首頁自動查詢走 `core/` 既有快取；一次打開最多 2 個 TDX 請求（通勤第一段＋即時資料格），其餘按了才查。

## 10. 天空與動畫

- 時段：深夜 00–05、清晨 05–07、白天 07–16、傍晚 16–18:30、夜晚 18:30–24（台灣時間）。
- 白天是淺色天空（深色文字）；只有夜晚與深夜是深色。首頁文字對比 ≥ 4.5:1，各時段都要測。
- 完整進場（星星、核心連線、卡片升起）一天一次，在 1.5 秒內；其餘打開只淡入 0.3 秒；`prefers-reduced-motion` 全部關掉。
- 藍鵲依卡片與天際線之間的可用高度決定是否畫，不做「擠到只露頭」。
- 手機狀態列：深色天空時用淺色圖示，離開首頁還原。
