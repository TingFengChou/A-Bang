# ADR-0017：回答也在手機上寫（Gemini Nano／Apple Intelligence，程式護欄檢查數字）

狀態：已採用（2026-11-21，產品負責人：「回答也改成在手機上寫」）

## 背景
ADR-0014 讓手機上的系統模型先「聽懂意圖與狀態」，ADR-0015 讓手機做語音轉文字與讀照片上的字；寫回答的仍是伺服器上的地端模型（qwen3:8b）或規則（示範模式），正式環境預計是 Claude。
手機上的模型已經在那裡、免費、不經網路。目標：**手機支援時，伺服器不呼叫任何 AI 模型（AI 成本為零），使用者的問題也不送到模型伺服器。**
同時數字一定要來自工具資料（ADR-0009）、方案排序由程式計分（ADR-0010）、行動只給連結（ADR-0011），手機上的小模型不能被信任去改數字。

## 決策
1. **分工**：伺服器照舊查資料（金鑰只在伺服器、共用快取）、程式計分排序、用規則路徑（`runDemo`）決定查哪些工具；判斷層只用快速版（嵌入分類器＋規則＋手機送來的 `deviceJudge`，**不呼叫伺服器的判斷模型**）。伺服器產生「程式版總結」（`demoSummary` 那一套，數字都來自資料）與精簡的「事實清單」，手機把總結改寫成自然的一兩句。
2. **請求與事件**（`docs/AGENT.md` §3、§3.5）：
   - App 裡、外掛 `status()` 回 `available: true` 且 `write: true`、裝置端 AI 與「回答也在手機上寫」兩個開關都開著時，請求帶 `clientCaps: { edgeWrite: true, engine: 'gemini-nano'|'apple' }`（zod `.strict()` 驗證，其他欄位一律 400）。
   - 伺服器此時不論 `LOCAL_LLM_URL`／Claude 設定都不呼叫模型：`status.mode = 'edge'`，走規則路徑，最後送 `answer_draft { text, facts, lang }` 再送 `done`，**不送 `text`**。
   - `facts`：`{ intent, lang, demo, points: [小幫手的一句話…], trip?: { departAt, best: { name, minutes, cost, arriveAt }, others: [...], arriveBy?, reason?, tips? } }`。不放座標、不放起訖點（可能是常用地點或現在位置）、不放使用者的句子。
   - 沒帶 `clientCaps.edgeWrite` 的請求（網頁版、不支援的手機、舊版 App、開關關掉）**行為完全不變**：伺服器照舊用設定的模型（Claude／地端）或規則回答。
   - 防詐 agent 一律不交給手機寫（帶了也照原路徑）；安全情境（S18 求助電話）照樣直接送 `text`。
3. **手機上寫**：外掛 `AbangEdgeAI.write({ draft, prompt, lang, instructions })`，指示與輸入由 JS 組好（`core/edge-write.js` 的 `WRITE_INSTRUCTIONS`、`writePrompt`，兩個平台共用）：約 80 字內、親切、先講結論（`docs/BRAND.md` §4），不得改動或新增任何數字、時間、站名、路線、金額，不加事實清單以外的資訊；英文那一輪用英文。
   - Android：ML Kit GenAI Prompt API（Gemini Nano，經 AICore），`generateContent`，溫度 0.2、topK 3、最多 160 token，原生端 2.3 秒取消。
   - iOS：Foundation Models（Apple Intelligence），每次新的 `LanguageModelSession(instructions:)`，`GenerationOptions(temperature: 0.2, maximumResponseTokens: 160)`，2.3 秒沒寫完就取消（task group）。
   - JS 只等 2.5 秒（`WRITE_TIMEOUT_MS`）；逾時、失敗、上一題還沒寫完 → 用程式版總結。程式版太長（> 220 字）或關鍵數字超過 10 個時不改寫（模型一定漏），直接用程式版。
4. **護欄是程式，不信任模型**（`core/edge-write.js` `checkRewrite`，純函式；伺服器以 `/core/edge-write.js` 提供給前端，App 打包時一起複製）。任何一條不過就用程式版總結：
   - 改寫裡的每個時間（HH:mm，`8:30`＝`08:30`、全形也認得）與數字（`1,350`＝`1350`）都要出現在程式版總結或事實清單裡；
   - 程式版總結的關鍵數字一個都不能少（名稱括號裡的出口編號不算）；
   - 國字或英文寫的數量（「兩分鐘」「five minutes」）不在草稿裡就算多出來的數字；
   - 不能說已經幫你叫車、訂票、付款（ADR-0011）；不能多出投資建議或漲跌預測；
   - 草稿裡的重要提醒（示範資料、末班、停駛、沒拿到你的位置、帶傘、時間很緊）要留著；
   - 引號裡的名稱要是資料裡有的；不能有草稿沒有的網址、工具英文名稱、markdown；
   - 語言要對（英文那一輪的中文只能是資料裡的名稱）；長度不超過上限；
   - 防詐 agent 一律不改寫（`WRITE_AGENTS = ['life']`）。
5. **看得到、照實說**：思考動畫多一個階段「在手機上寫回答」（收到 `answer_draft` 後、改寫完成前；真實事件驅動）；回答上方只有一行，把手機判斷與寫回答合在一起照實說：手機判斷被採用且寫好回答 →「手機上的 Gemini Nano 聽懂你的問題，也寫了這次的回答。」；只有寫回答 →「這次的回答由手機上的 Gemini Nano 寫。」；沒通過檢查或逾時 →「手機上的 Gemini Nano 聽懂你的問題；回答用阿幫的固定說法（沒通過檢查／逾時）。」（沒有手機判斷時「這次的回答用阿幫的固定說法（…）。」）；英文同理，iPhone 照實寫 Apple Intelligence（`writeLine`）（2026-11-21 產品負責人：「合成一行」）。設定頁「裝置端 AI」加開關「回答也在手機上寫」（預設開：成本零、問題不送模型伺服器）；「阿幫的腦袋」頁（`#/ai`）加「寫回答」一格：引擎、開關、今天在手機上寫了幾次、上次花多久、改寫通過檢查的比例（`localStorage abang.edgeWriteStats`，只有數字、只存在這支手機）。
6. **伺服器模型的角色**：網頁版與不支援的手機仍用伺服器的模型（有設定時）或規則；`AGENT_DAILY_BUDGET` 等成本控管照舊。手機寫的那一輪 log 記 `mode: 'edge'`（不含內容），可算出省下多少模型呼叫。

## 不採用
- **手機直接回答（不經伺服器）**：金鑰只在伺服器、數字要來自工具資料、計分要一致（ADR-0010），伺服器仍是唯一查資料與排序的地方。
- **讓手機模型自由寫、只靠提示詞約束**：小模型會改數字（實測常把「7 分」寫成「幾分鐘」或換算時間），一定要程式檢查。
- **檢查不過就請模型重寫**：多花時間（每次約 0.5～2 秒），程式版總結本來就正確，直接用。
- **連防詐也改寫**：固定安全句（165、先不要照做）一個字都不能少，改寫沒有好處。

## 影響
- 新事件 `answer_draft`、新請求欄位 `clientCaps`、新模式 `edge`（`status.mode`）。舊版 App（外掛沒有 `write`）`status()` 沒有 `write: true`，不會帶 `clientCaps`，行為與原本相同。
- 手機寫的那一輪，回答品質取決於規則路徑能不能聽懂（意圖由規則＋分類器＋手機判斷決定）；規則聽不懂的問題（模型模式才答得好的開放問題）會回規則的說明。產品負責人決定（2026-11-21）：**一律不用伺服器模型**；聽不懂時照規則的說明列出阿幫查得到的內容。主線合進「阿幫問你」（PR #107）後，聽不懂時可改用 ask 給幾個查得到的選項（待整合）。
- 站名的檢查只看引號裡的名稱；沒加引號的新站名靠指示詞約束（數字是主要風險，已由程式完整檢查）。
- 卡住：Gemini Nano 與 Apple Intelligence 的改寫品質、通過率、延遲要實機量（Pixel、iPhone 15 Pro 以上）。
