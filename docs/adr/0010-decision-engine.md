# ADR-0010：依「MCP 資料＋使用者狀態」做決策，規則透明、由程式計分

狀態：已採用（2026-11-17）；實作 `core/decide.js`、測試 `test/decide.test.js`、原型 `docs/prototypes/transit-discussion.html`

## 背景
Austin 的要求：MCP 資料回來後，阿幫要依**資料與使用者狀態**判斷並給出最佳決策，而且決策過程要有動畫、看得懂。考量要包含價格與交通狀況（例如塞車就建議台鐵或高鐵），YouBike 保留，叫車之後可串 Uber。

## 決策
1. **分工**
   - 工具（MCP）：提供事實（時間、班次、價格、車數、路況、天氣）。
   - 決策引擎 `core/decide.js`：純函式、規則透明、可測試，替方案計分排序並產生理由句。**不經模型**。
   - 模型：判斷使用者狀態（從對話）、決定要問哪些工具、用口語轉述結果。不自行計分或改寫分數。
2. **比較項目**（都是越小越好）：總時間、等車、走路、費用（以「最佳值／本方案」比例計分，不被極端值壓扁）、淋雨、體力、塞車風險（0–1 程度值）。
3. **使用者狀態**調整權重：趕時間、塞車中、下雨、帶行李、想省錢、少走路、空品不佳（M10）。狀態來源三種，畫面上要標示：
   - **自動判斷**：由 MCP 資料推得（天氣回報下雨 → 下雨；路況回報壅塞 → 塞車中；起點空品 AQI > 100 → 空品不佳）
   - **你說的**：從對話取得（「10 點前要到」→ 抵達時間限制；「我帶著行李」→ 帶行李）
   - **你選的**：使用者在畫面上點選
4. **硬限制**：指定抵達時間時，會遲到的方案直接排除並說明。
5. **決策過程動畫：決策圖**（淺色、交通語意，參考影片的「節點與流動」手法但不移植其風格）
   - ① 收集資料：左側是本次用到的資料來源（地點、天氣、路況、公車、YouBike、高鐵、台鐵、票價、叫車），每個來源回報時，一個帶著真實數值的資料膠囊（例：「小雨」「12分到」「8台」）沿線流向中間的阿幫。
   - ② 看你的狀況：狀態標籤浮現在阿幫上方，並以虛線連回推得它的資料來源（天氣 → 下雨・自動）；「你說的」條件同時顯示。
   - ③ 比較：阿幫到右側各方案的連線依分數逐項變粗；會遲到的方案變成紅色虛線並標「遲到」。
   - ④ 決定：最佳方案亮起並持續有光點流動；左側「讓它勝出的資料來源」同步亮起（例如下雨時亮天氣、塞車時亮路況），其餘淡出；下方一句理由。
   - 切換狀態即時重算並重播 ③④；逐項分數長條收在「看比較細節」。
   - 原則：畫面上的數字與連線都來自真實資料與 `core/decide.js` 的結果，不做裝飾性的假流動。
6. **方案來源可擴充**：公車、YouBike、步行、捷運、台鐵、高鐵、國道客運、叫車（Uber 等，以 provider adapter 介接，先做深層連結，估價 API 待合作）。

## 影響
- `plan_trip` 輸入加 `prefs`（狀態與抵達時間），輸出 `ranking`（含 breakdown 與 reason）；網頁與 MCP Apps 卡片都依此畫動畫。
- 事件協定新增 `decision`（`AGENT.md` §3.1）。
- 權重屬於產品決策，調整需更新測試並記錄於本 ADR。

## 權重調整紀錄
- 2026-11-18（M3-11）：「想省錢」`cost` 倍數 3 → 5。原因：市區短程（台北車站→台北101）叫車約 255 元、公車 15 元，×3 時兩者同分、叫車以時間較短勝出，不符合「想省錢」。×5 時公車第一、叫車最後；跨城（新竹）仍是客運第一。測試：`test/decide.test.js`「想省錢」、`test/trip-od.test.js`。
- 2026-11-18（M5-13）：非權重調整、記錄供參——班次制方案（軌道、客運）的等車最多算 10 分（再多視為晚點出門），避免很早出發時總時間被等車灌水；跨城＋塞車情境的最後一名因此從客運變為叫車（`test/trip-od.test.js`）。
- 2026-11-19（M10）：新增狀態「空品不佳」`badAir`（`exposure` ×3、`effort` ×2），`plan_trip` 起點最近測站 AQI > 100（對敏感族群不健康以上）時自動加入；比較項目 `exposure` 標籤由「淋雨」改為「戶外」（下雨淋雨、空品差吸髒空氣都算），理由句只有空品不佳且沒下雨時說「少待在戶外」。市區短程＋空品不佳：叫車第一、步行最後（`test/trip-od.test.js`）；西門町→101 三方案：公車第一（`test/decide.test.js`）。
- 待 Austin 決定：無狀態時市區短程（1.5～5 公里）叫車排第一（走路 0、淋雨 0、體力 0 的優勢大於約 250 元的費用差）。若希望預設偏向大眾運輸，可提高 `cost` 基本權重或降低 `walkMin`；改了要同步 `test/trip-od.test.js`。
