# ADR-0023：首頁改版「夜色與光」——依時間變化的天空、一張「現在的建議」、底部輸入列取代分頁列

- 狀態：**已採用**（2026-11-29，Austin 選定設計 A；細部取捨依 Austin 指示由 Claude 與 Antigravity 共同決議，第十九輪）
- 相關：ADR-0009（淺色主題、不做深色 HUD）、ADR-0010（決策由程式計分）、ADR-0011（行動需確認）、ADR-0014／0017／0020（裝置端 AI）、ADR-0018（健康資料只在手機）、ADR-0021（裝置動作由系統畫面確認）
- 規格：`docs/HOME_REDESIGN.md`；原型：`docs/prototypes/home-night-light.html`（假資料，不可被 import）

## 背景

2026-11-28 Austin：「現在設計，尤其首頁，還是很傳統。」舊首頁是「今天卡＋主視覺＋防詐大卡＋三組格子」，本質是入口網站：照政府部門分類、要使用者先知道自己要點哪一類；「問阿幫」與格子是兩個平行世界。

同時 Austin 指出：「我們不是大語言模型，很難只有 chat 就可以完成。」所以首頁不能變成聊天框；大部分事情要靠「直接看到資料」完成。

三位設計（設計師 A「夜色與光」、設計師 B「晚報 × 儀表」、Claude「核心＋能力列」）各做了會動的原型，Austin 選 A；之後經兩位 UX（認知走查、互動與文案）審查與 Austin 多輪意見修正。

Austin 明講、不能違反的要求：

1. 功能不可以少。
2. 跟別人不一樣的特色要外顯。
3. 用詞正式（稱呼用「您」）。
4. 要能從目前位置出發。

## 決策

### 1. 首頁是一片依時間變化的天空，上面只有一個焦點

- 整頁背景是天空：深夜與夜晚是夜空（有星星與台北 101 天際線）、清晨是晨色、白天是日間的淺色天空、傍晚是暮色。只看台灣時間，不看位置。
- **這是 ADR-0009「淺色主題、不做深色 HUD」的首頁例外**：只有首頁、而且只有夜間時段是深色；其他頁面（服務、問阿幫、提醒、個人、各資料頁、對話框）一律維持淺色。首頁的文字對比仍須 ≥ 4.5:1。
- 天空上方是「手機上的 AI」核心（Λ＋琥珀核心＋軌道，沿用「阿幫的腦袋」的圖形語彙），旁邊一個金色頭腦圖示（不放文字；點了浮出「手機上的 AI・引擎名稱」，並可進「阿幫的腦袋」頁）。核心只連到**這次建議真的用到的訊號**。
- 藍鵲是吉祥物、不是思考的主體：小小地站在天際線邊；版面放不下時不顯示。

### 2. 一張「現在的建議」卡，只有一顆主按鈕

- 卡片回答三件事：這是什麼建議、從哪到哪（或看了什麼）、按了會發生什麼。
- 情境由程式的規則決定（延續 ADR-0010 的精神：程式判斷、模型不編數字），見 `docs/HOME_REDESIGN.md` §3。
- **通勤與返家是「固定通勤方式的今日狀況」**，不是每天叫人查路線：顯示固定路線、班次狀況、下一班、建議出門時間、預計抵達時間。
- **出發地可以切換**（固定地點｜目前位置）；已允許定位時，打開 App 讀一次位置，不在固定地點附近就自動以目前位置為出發地並標示。
- 猜錯有出口：「其他建議」與底部的「您可能想問」是同一份清單（展開同一個面板）。
- 行動仍照 ADR-0011、ADR-0021：只產生連結或交給系統畫面確認；按了才查、按了才取位置。

### 3. 底部輸入列取代分頁列

- 拿掉底部分頁列（首頁｜服務｜問阿幫｜提醒｜我的）。
- **底部輸入列（相機、輸入框、麥克風）＋「您可能想問」提示列**常駐在首頁與一級總覽頁（全部服務、提醒、個人）。
- 內容頁（公車、天氣…）保留一顆精簡的「問阿幫」浮動鍵，拉出同一段對話（維持「知道您在哪一頁」的既有功能）；問阿幫頁用它自己的輸入區；設定、表單、對話框不顯示。
- 提醒泡泡改從輸入列（或浮動鍵）冒出。
- Android 返回鍵：有上一頁就回上一頁，在首頁才離開 App（不寫死回首頁）。
- 提醒與個人移到首頁右上角兩個圖示鍵。
- 第一版輸入列送出後開啟既有的問阿幫；「打字即出卡」列為第二階段，元件先預留候選區介面。

### 4. 特色外顯、依平台據實顯示

- 「更多功能」區只列這支手機做得到的：拍照查詢、Siri 語音查詢（iOS）、主畫面小工具（Android；iOS 待付費開發者帳號）、出門倒數（iOS 鎖定畫面與動態島、Android 通知列）、加入行事曆與分享、散步提醒。做不到的不顯示。
- 不自動輪播；每張卡都能按（試用或了解）。

### 5. 資料誠實

- 公車到站是即時資料。
- **捷運班次一律標「依時刻表」**（TDX 的北捷看板沒有倒數分鐘）。
- **算不準就不寫「延誤幾分」**：只顯示「下一班 N 分」；只有拿得到該時段班距、且 N 明顯大於班距時才標「班次間隔較長」並建議改搭。
- 查不到不說成沒有；示範資料、離線都要標示（沿用降級原則）。
- 首頁自動查的班次必須走快取與額度排程；額度用完照實顯示「這次查不到班次」。

### 6. 隱私

- 固定通勤方式、住家、公司、活動資料、上次的對話都只存在手機。
- 只在已允許定位或使用者按下時讀一次位置；不背景追蹤。
- 快速設定住家：存之前一定先顯示「設為：○○區○○附近」的確認預覽，可改。
- 「為何顯示此建議」頁列出這次用了哪些資料，以及阿幫記得的東西（可逐項刪除）。

### 7. 用詞

- 全 App 稱呼改用「您」，語氣正式但不生硬。首頁先用，接著以獨立 PR 全站統一，兩者同一版上線。

### 8. 解除驗收凍結（範圍限定）

`docs/PLAN.md`「V 整體驗證」期間原本暫停新功能。Austin 2026-11-29 指示進入開發；**解凍範圍只限本次首頁改版相關項目**（`docs/HOME_REDESIGN.md` 的分期），其餘新功能仍暫停。

## 不採用

- **純對話式首頁**（原型 A 對話泡泡）：不是大語言模型，只靠聊天完成不了事。
- **卡片流**（原型 B 一張主卡＋小卡）、**語音優先**（原型 C）：Austin 不採用；語音還沒實機驗證。
- **活的格子／便當盒**（原型 D）：格子一多又是貨架；沒有即時數字的服務（防詐、政府辦事）放成格子很空。
- **晚報 × 儀表**（設計師 B，淺色編輯式）：最符合淺色原則、也最好讀，但 Austin 選擇更有氣氛的 A；它的兩個做法被 A 的修正版吸收（訊號用引線連到核心、藍鵲指向核心）。
- **每天查詢通勤路線**：通勤是固定的，使用者要的是今天的狀況。
- **自動輪播的能力卡、右上角一排能力小圖示、繞著核心的能力衛星**：突兀、新手看不懂、長輩讀不完。
- **從使用者常出現的位置推測住家**：需要長期記錄位置，違反不追蹤原則。
- **讀取 Google 地圖／Apple 地圖裡使用者標的住家**：兩家都沒有開放給其他 App 的介面。

## 影響

- `public/js/pages/home.js`、`public/js/today.js` 重寫；`public/js/tabs.js`、`public/js/abang-dock.js`、`public/js/app.js` 的分頁列與中央鍵改成輸入列與浮動鍵。
- 既有 e2e 中首頁與分頁列相關的測試要改寫；功能對照表（`docs/HOME_REDESIGN.md` §2）逐項驗收，確保功能不減。
- `docs/UX.md` §1 的「淺色、簡單、手機優先」加註首頁例外；`test/a11y.test.js` 要加首頁夜間配色的對比檢查。
- Android 主畫面小工具「阿幫・今天」的內容來源改為新的建議規則。
- 手機狀態列顏色要跟著首頁天色（深色時用淺色圖示），離開首頁還原。
- 桌面寬螢幕（網頁優先）需要另外的版面；白天整頁的淺色天空也要補設計（第 0 期）。
