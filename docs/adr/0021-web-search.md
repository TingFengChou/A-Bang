# ADR-0021：開放資料查不到時，用網路搜尋補（邊界先講清楚）

狀態：**提議**（2026-11-23，等產品負責人確認）。產品負責人：「可以搭配 web search tool 嗎？如果查不到的話，我記得 Apple Intelligence 可以」「但是要把邊界限定清楚」。

## 背景
阿幫的答案來自政府開放資料與合作來源（TDX、氣象署、環境部、165、MyDrama…），數字都來自真實資料（ADR-0009）、方案由程式計分（ADR-0010）。
有些問題開放資料沒有，例如「捷運今天為什麼停駛」「101 跨年煙火幾點」「這週末花博開到幾點」。現在只能說查不到。

關於 Apple Intelligence：我們用的是 Apple 的 Foundation Models（手機上的模型，ADR-0014）。據目前所知，這個模型給 App 用時不會自己上網；Siri 轉問 ChatGPT 的功能也沒有開放給 App 呼叫。所以**搜尋要由伺服器做**，手機上的模型只負責判斷和改寫（⚠️ 若 Apple 之後開放，再更新這份 ADR）。

## 提議的邊界
1. **什麼時候搜**：只在「開放資料查不到、而且是生活資訊」時——意圖是事件、營業時間、停駛或異常的原因、活動資訊。
   - 不搜：交通方案（時間、票價、到站）、天氣、空品、地震、藥局、垃圾車、油價、發票、股市這些**有開放資料的**；醫療判斷、法律、投資建議；防詐判斷（防詐只看 165 與規則庫，ADR-0012）。
2. **搜什麼**：搜尋句由程式組（意圖＋地名＋主題），不直接拿使用者原句；**不帶**定位座標、常用地點、姓名、電話、帳號、健康資料或對話前文。
3. **搜哪裡**：只收白名單網域的結果——政府（`*.gov.tw`）、營運單位官網（北捷、桃捷、高捷、台中捷運、台鐵、高鐵、各縣市公車處）、主要地標與場館官網（清單放 `core/data/web-allow.json`，每加一個要審查）。白名單外的結果丟掉，不給模型看。
4. **怎麼說**：網路結果另外標「網路上查到的（來源：網域、時間）」並附連結；**不參與**決策計分、不當成「真實資料」的數字；跟開放資料衝突時以開放資料為準並照實說。
5. **頻率與成本**：每一輪最多 1 次、每支手機每天上限（例 20 次）；示範模式不搜；設定頁可以關（預設開或關由產品負責人決定）。
6. **誰執行**：伺服器的工具 `web_lookup`（照 ADR-0007 標 `pack: 'web'`、`tier: L1`），用 Claude 的網路搜尋工具或其他搜尋 API（需要金鑰時屬停止條件，先問）；地端模型模式不提供。
7. **輸出護欄**：結果文字過 L2 護欄（不出現付款、匯款、加 LINE 等字眼）；有「中獎」「退款」類內容一律不轉述。

## 要產品負責人決定的
- 預設開還是關？
- 白名單第一批放哪些網域？
- 搜尋服務用哪一家（Claude 網路搜尋需要 API 金鑰與費用）？

## 影響
- 好處：開放資料以外的生活問題不再只說查不到；來源清楚、使用者可以點進去看。
- 代價：多一個外部服務與費用；要維護白名單；回答會慢一點（只在查不到時才搜）。
