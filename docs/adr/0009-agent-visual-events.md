# ADR-0009：交通 agent 以「小幫手討論串」呈現多 MCP 協作

狀態：已採用（2026-11-17）；原型 `docs/prototypes/transit-discussion.html`

## 背景
Austin 希望阿幫「很自動」、看得到多 MCP 互相配合；純文字串流太無聊。他給的兩支影片只是動畫感覺的參考。第一版原型移植了影片的深色 HUD，被退回：不適合民眾、不適合交通類 MCP、太複雜。回饋要點：**先以交通為主、簡單一點、呈現 MCP 互相討論的過程、不要深色**。

## 決策
1. **呈現方式：小幫手討論串**（淺色、手機優先、延續阿幫品牌）
   - 阿幫居中協調，以 `@公車`、`@YouBike`、`@高鐵`、`@票價` 點名工具。
   - 每個工具以「角色」身分用一句話回報（例：「西門站還有 8 台，騎過去約 25 分。」），並標示背後的 tool 名稱與 MCP 來源（阿幫 MCP、TDX 官方 MCP）。
   - 討論結束後自動收合成一行摘要（「小幫手討論完成・4 個工具・1 個 MCP」），可展開回看。
   - 接著出現**結論卡片**（建議方案、各段時間條、備案、行動按鈕），卡片內的倒數與車輛位置持續即時更新；最後阿幫用一兩句話總結並主動提議（例：「要我 05:45 叫你出門嗎？」）。
2. **誠實對應**：MCP 伺服器之間實際上不會互相對話，是阿幫（模型）依前一個工具的結果決定下一步。討論串是真實事件的忠實呈現：
   - 阿幫的話 ＝ `agent_note` 事件（模型輸出的簡短、給使用者看的理由；不是完整思考過程）
   - `@工具` ＝ `tool_start`
   - 工具的話 ＝ `tool_result.speak`（由 tool 的 `speak(data)` 依真實資料產生的一句話，**不經模型**，避免捏造數字）
   - 平行呼叫的工具依完成順序發言
3. **數字必須真實**：不加假延遲、不編造進度；只允許最短顯示時間（約 300ms）避免閃爍。
4. **事件協定**見 `AGENT.md` §3.1；遠端 MCP 的結構化結果同樣附 `speak`，讓支援 MCP Apps 的 client 也能呈現。
5. 遵守 `prefers-reduced-motion`；不使用深色主題作為預設。

## 不採用
- 深色指揮中心 HUD（粒子地圖、扇形圖、儀表）：適合開發者展示，不適合民眾查交通。
