# UX 規格 — 阿幫・生活（交通）

版本：v0.4（2026-11-17）。參考原型：`docs/prototypes/transit-discussion.html`（瀏覽器直接開；4 個情境）；Agent 互動模型：`docs/prototypes/agent-interaction.html`（股市、發票掃描、選公車後盯到站＋提醒；右邊即時顯示事件流、模型看得到的歷史與卡片脈絡、命中的規則）。
正式實作在 `public/js/pages/agent.js`（✅ M5-08，`#/agent`）＋ `public/css/agent.css`，**由真實 NDJSON 事件驅動**（`AGENT.md` §3），原型中的假資料與 `sleep()` 只是示意。頭像：阿幫用吉祥物（`/brand/abang-think.svg`，與原型相同），每個小幫手是角色色彩圓形＋線條圖示（`public/js/icons.js`，與首頁格子同一套；`role=img`＋`aria-label` 念角色名）。

## 1. 原則

1. **淺色、簡單、手機優先**：不做深色 HUD；一屏只講一件事。
2. **看得到多 MCP 在合作**：阿幫點名工具、工具一句話回報（ADR-0009）。
3. **看得懂為什麼這樣建議**：決策圖把「資料＋你的狀態 → 建議」畫出來（ADR-0010）。
4. **誠實**：數字與發言來自真實資料；不加假延遲；估算一定標「估算」。
5. **可以行動**：結論卡片直接提供導航、訂票、叫車、提醒。
6. **可及**：`prefers-reduced-motion` 關閉動畫；色彩不是唯一資訊來源；觸控目標 ≥ 44px。

## 4. 小幫手討論串

| 事件 | 呈現 | 時間 |
|---|---|---|
| `agent_note` | 阿幫頭像＋泡泡；`@角色` 以該角色色彩的 chip 顯示 | 打字指示 ≥ 300ms 後出現 |
| `tool_start` | 對應角色頭像出現「輸入中…」三點；右下小字 `tool 名稱 · MCP 來源` | 立即 |
| `tool_result.ok` | 「輸入中」換成 `speak` 一句話；右下加 `metrics`（例：`37 筆 · 快取`） | 與前一則間隔 ≥ 300ms（只為避免閃爍） |
| `tool_result` 失敗 | 灰色泡泡「這次沒查到（原因）」；不中斷其他工具 | — |
| `discussion_end` | 整串收合成一行：「小幫手討論完成・5 個工具・1 個 MCP」＋展開箭頭 | 收合動畫 250ms |

角色對照（`tool_start.role` → 名稱、色彩、圖示）：地點 place、天氣 place、公車 bus、YouBike bike、高鐵 rail、台鐵 tra、捷運 brand、路況 car、客運 car、票價 fare、叫車 car、訂票 rail。圖示為簡單線條 SVG（`public/ui/icons.js`），不要用表情符號。

## 5. 決策圖（`decision` 事件）

由左到右四欄：**資料**（工具）→ **你的狀態** → **方案** → **建議**。SVG，寬度自適應，高度依方案數（每方案 44px）。

動畫順序（總長約 2.4 秒；reduced-motion 時直接顯示最終狀態）：

| 步驟 | 內容 | 時長 |
|---|---|---|
| 1 | 資料欄：每個工具節點亮起，資料膠囊（小圓點）沿線流向「狀態」 | 600ms |
| 2 | 狀態欄：每個狀態標籤淡入；自動判斷的狀態以虛線連回產生它的工具（`CRIT_SRC` 對應：戶外 ← 天氣（空品不佳且沒下雨時 ← 空品）、塞車風險 ← 路況、費用 ← 票價；空品不佳 ← 空品） | 400ms |
| 3 | 方案欄：方案依分數由高到低翻轉排序（FLIP，`rotateX`）；連線粗細 = 分數 | 600ms |
| 4 | 被硬限制排除的方案：灰階、刪除線、標註「會遲到」 | 200ms |
| 5 | 勝出路徑（勝出方案 ← 關鍵比較項目 ← 資料來源）亮起，其他淡出到 30% | 400ms |
| 6 | 「為什麼」一句話（`decision.reason`）出現 | 200ms |

**狀態 chips**（決策圖上方）：

- 自動判斷：`自動：下雨`（來源工具的色彩點＋可點 ✕ 關閉）
- 你說的：`你說的：帶行李`
- 你選的：可加選 chips（趕時間、想省錢、少走路、帶行李）
- 點任何 chip → 前端以同一份 `decide.js`（`/core/decide.js` 以 ES module 提供給瀏覽器）立即重算，重播步驟 3–6；不呼叫伺服器。
- 關掉某個自動狀態時，理由句改為「不考慮『下雨』的話，…」。

**明細**：每個方案可展開長條圖（各比較項目得分 × 權重），標示最影響結果的兩項。

✅ M5-09：`public/ui/agent/decision-graph.js`（`renderDecision(root, decision, { sources, decide, CRITERIA })`，SVG 以 DOM API 建立、含 `<title>`／`<desc>` 文字替代）；伺服器以白名單提供 `/core/decide.js`；`plan_trip` 輸出與 `decision` 事件帶 `arriveBy`／`arriveByMin` 讓前端重算與伺服器一致（`test/agent-events.test.js` 驗證）。動畫為 CSS 分段淡入（步驟 1–6），排名翻轉（FLIP）與 3D 留待 M5-11。

### 4.9 首次使用引導（2026-11-21）

第一次打開首頁時（深層連結直接打開的頁面不打斷）跳出 `<dialog>`：①「嗨，我是阿幫」能問什麼＋點決策圖方案可改選、②「用你現在的位置當起點」＋「允許定位」（按了才跳系統對話框；不給也能用；位置不存到伺服器、常用地點只存在手機）、③（只有 App）「公車快到時提醒你」＋「允許通知」。網頁版不在這裡要通知：設定到站提醒時才要。已經允許的權限步驟跳過；每步可「略過」（橫放時固定在上方）、Esc 或 Android 返回鍵關閉；換步驟時焦點停在標題；權限結果用 `role=status` 並由下一步按鈕的 `aria-describedby` 一起念，失敗用灰字說明怎麼開。矮螢幕收起插圖。iOS 15.0～15.3 沒有 `<dialog>`：不顯示。看過記在 `localStorage` `abang.onboarded`（清除本機資料會一起清，下次再顯示）；引導開著時開獎對獎延到關掉之後；「設定與隱私」底部「再看一次使用說明」。`public/js/onboarding.js`。

### 4.10 離線與弱網（2026-11-21）

只存明確允許的查詢（`public/js/api.js` `cache`）：公車到站時間 10 分鐘、路線與時刻表 24 小時；參數有座標的一律不存。最多 30 筆、整份 300 KB 以內（不擠掉收藏與我的發票），過期的刪掉。連不上、8 秒沒回應、閘道錯誤（502／503／504）、或回應不是我們的 JSON（公共 Wi-Fi 登入頁）時先顯示上次的資料；4xx 照實說錯誤。最上面常駐的黃底 live region（文字變了才更新）：「目前離線：顯示 14:05（或昨天 14:05）存下的資料，可能不是最新。」；公車頁尾改成「離線：這是 … 存下的資料」，不念「即將進站」、不給到站提醒（時間不準）。換頁清掉標示；連回來重新載入這一頁。沒存過的、卡片工具連不上都說「目前連不上網路，連上後再試一次」（不是 Safari 的英文 Load failed）。示範單檔版不顯示。清除本機資料一併清掉。

### 4.11 下車提醒（2026-11-21）

公車頁時間軸點站名就能設成上車站（站名虛線底線、整列寬的按鈕、`aria-pressed`；網址的 stop 與 dir 一起改；焦點移到上車站卡片；每 20 秒重畫焦點留在原處；上方提示「點站名設成上車站…」，選了之後改成「點其他站名可以改上車站」）。換上車站時原本的到站／下車提醒照舊，在上車站卡片上寫「另有提醒…」並可取消。選了上車站後，上車站卡片下方：「上車了嗎？要在哪一站下車？」下拉（只列上車站之後的站，值是站序，環狀路線同名站不會選錯；每 20 秒刷新不會重選）＋「快到時提醒我下車」。判斷「我這台」：沿站序從上車站往後第一個到站時間變小的站，就在剛離開上車站那台車的前方；目的站在它前方且中間沒有別台車＝目的站的下一班就是我這台，剩 ≤ 2 分提醒。設定時車正要進站（≤ 90 秒）＝等這台；看不出來時照站數 × 90 秒。進行中顯示「下車提醒：快到「X」時提醒你（約 N 分後到）」與「取消下車提醒」（不加 live role，避免每 20 秒重念）；沒有通知權限時寫明 App 關著不會提醒。快到時 toast「🔔 約 2 分後到「X」，準備下車」＋震動。App 設定當下就排好通知（第一次查失敗也會響），每次更新改時間；被系統關掉重開時，通知已響過就清掉不重響。`public/js/alight.js`。

### 4.12 定位失敗說原因（S1c，2026-11-21）

定位失敗分四種原因（`public/js/agent/client.js` `locationReason`：原生外掛錯誤碼 `OS-PLUG-GLOC-*`、網頁 `GeolocationPositionError`）：權限沒開（denied）、手機定位服務關閉（off）、太久沒回應（timeout）、其他（unavailable）。說明與按鈕在 `public/js/location-help.js`：
- 附近、生活服務頁：清單上方黃底說明「原因＋下一步＋現在先用台北車站附近」，按鈕「再試一次」；App 裡權限或定位服務關閉時多一個「到設定開啟」（專案內外掛 `AbangSystem`：Android 權限開 App 設定、定位服務開系統定位設定；iOS 只能開 App 設定），從設定回來自動再定位一次。
- 問阿幫：定位泡泡依原因說（「定位權限沒有打開；可以直接打地點，或到設定允許定位」），App 裡附「到設定開啟」。
- 設定頁：權限區定位「已拒絕」時（App）多「到設定開啟」；Android 拒絕過一次（`prompt-with-rationale`）顯示「拒絕過一次（下次用到會再問）」；畫面再出現時重新檢查。設成現在位置失敗時提示說原因。
- 首次使用引導：允許定位失敗時說原因。
- 網頁版沒有開設定的按鈕：說「到瀏覽器的網站設定，把『位置』改成允許」（安裝成 PWA 沒有網址列）。
- iOS 的定位服務總開關不在 App 設定頁：定位服務關閉時只說路徑「設定 → 隱私權與安全性 → 定位服務」，不給按鈕。打不開設定時說「打不開設定，請自己到手機的設定開啟」。

### 4.13 行程中模式（2026-11-21）

- 公車頁設了下車提醒＝坐車中：上車站卡片換成「坐車中・從「上車站」上車」＋大字「約 N 分到「下車站」」（`rideLeftSec`：最近一次查到的時間扣掉經過的時間），不再給到站提醒按鈕；下面只說「快到「下車站」前約 2 分提醒你」與取消。街景的站牌換成下車站（讀屏「你在車上，在「X」下車」），看得出下車站的下一班是我這台才畫公車與站數，否則只寫剩多久；時間軸下車站標「你在這下車」。取消或提醒響了自動回到等車中。
- 進行中列（`public/js/trip-bar.js`）：有下車提醒或到站提醒時，每一頁上方一條列「307 坐車中・約 6 分到「市府」　看行程 ›」（坐車中，品牌色實底）或「307 在「和平體育館」上車・約 5 分到站　看公車 ›」（等車中淺色），點了回到公車頁（帶上車站與方向值）；在同一路線、同上車站與方向的公車頁不顯示。每 30 秒與回到前景時更新分鐘；不是即時區域（不打斷讀屏）；「›」不念；reduced motion 時圓點不閃。
- 設下車提醒＝已上車：同路線的到站提醒自動取消（提示說「到站提醒已取消」），避免在車上響「快到站」。車還沒進上車站時（設定時車 ≤ 90 秒）說「車快到「X」了，上車後開始算」。
- 問阿幫選了公車：有車要來、還沒設下車提醒時，「接下來可以」的「開公車頁看動態」換成「上車後提醒我下車」→ 公車頁 `?alight=1`，焦點直接在選下車站（卡片上仍有開公車頁按鈕）。

### 4.15 公車會動（2026-11-21，Austin：「公車會動吧，讓他動起來」）

公車街景兩次更新之間（20 秒）照到站時間往站牌慢慢開（`driveTo`：開 20／到站秒數的距離，最多到站牌前一點；還很遠停在畫面左邊不動），開車中車身微微震動前後晃；到站時煞車點一下再停著輕晃。站數沒變的更新從剛剛開到的地方繼續，不往回跳；站數變了照資料重新定位。reduced motion、精簡模式：不動。

### 4.14 阿幫常駐：對話保留與浮動阿幫（2026-11-21，Austin：「請阿幫跳去看公車動態，整個紀錄都會不見」）

- 對話保留：問阿幫頁（生活、防詐）只建一次（`public/js/abang-dock.js`、頁面 `keepAlive`）；換頁時整個畫面收起來不清掉，回來原樣接上（文字、卡片、決策圖、「接下來可以」、捲動位置）。只在這次開著的 App／分頁的記憶體，不寫到手機或伺服器。從首頁帶問題過來（`?q=`）接在原本的對話後面。
- 浮動阿幫：問阿幫頁以外，右下角（分頁列上方）藍鵲按鈕 60px；有對話時右上角小點、讀屏「打開跟阿幫的對話（對話還在）」。點了用 `<dialog>` 從下方拉出同一段對話（約 88% 高、背後頁面還在、點背景／Esc／Android 返回／「收起」收回，焦點回到按鈕）；「整頁」到問阿幫頁。阿幫帶你去別頁（開公車頁、卡片連結）時面板自動收回，對話不會不見。不支援 `<dialog>` 的舊瀏覽器改到問阿幫頁。鍵盤打開時隱藏。
- 提醒由阿幫說：到站、下車、公車一直不來時，提醒記在對話裡（藍鵲頭像＋淺綠底），在其他頁面浮動阿幫跳一下並冒泡泡（12 秒，「知道了」關閉；公車一直不來「要我幫你改其他方式嗎？」＋「改其他方式」→ 打開對話直接問）。生活對話看得到時不再跳提示；防詐頁等看不到的地方用提示。reduced motion 不跳。
- 頁面底部多留 84px（問阿幫頁不用），捲動時浮動阿幫縮小變淡、停下恢復，不擋住內容。
- 防詐對話不保留：貼上的可疑訊息離開頁面就清掉（共用手機時不留在畫面上）。
- 對話裡只有最近兩輪的卡片自動刷新；收起的對話（不在畫面上）的卡片不刷新（省流量與電）。阿幫還在回答時又來的問題（提醒泡泡、首頁）答完接著問。
- iOS 鍵盤打開時底部面板跟著可見高度往上（`keyboard.js` 設 `--vvh`、`--kb`）；打字中（鍵盤開著）提醒改用提示。

**我的發票（本機，M10）**：服務頁「發票對獎」卡片下方。輸入 8 碼號碼＋消費日期 →「存起來，開獎自動對」，已開獎的期別立刻出結果，沒開獎的顯示「M/D 開獎」。號碼只存在手機（localStorage `invoices`，最多 100 張），對獎時經 `invoice_check_batch` 比對、伺服器不保存。**主動**：每次打開 App，開獎日已到的發票自動對獎，中獎時 toast（已允許通知時另發系統通知）、沒中時說「已對獎，這期沒中」；問阿幫查發票時提議存到「我的發票」。網頁沒有背景排程：App 沒打開就不會對，下次打開才對（不需推播伺服器、不保存使用者資料）。不串 Gmail、載具（需保存使用者帳號或憑證，屬 ADR 變更）。
**掃發票**：「掃發票 QR code」開相機視窗（`<dialog>`，`public/js/invoice-qr.js`），對準電子發票證明聯**左邊**的 QR code，一張接一張掃（同一張只存一次、存到時震動），按「完成」或 Esc 關閉並停相機，再一次對獎。掃到右邊明細 QR（`**` 開頭）提示改掃左邊；中間一維條碼只有期別也可以存。只取字軌號碼與開立日期，不保存統編、金額、品項；影像只在手機辨識不上傳。用瀏覽器內建 `BarcodeDetector`（Android Chrome、macOS Chrome 支援；iPhone Safari、Firefox 不支援 → 顯示「請手動輸入」，不加第三方掃碼套件）。相機需要安全連線（HTTPS 或 localhost）。

**接下來可以…（2026-11-20，使用者回饋）**：一開始輸入框上方是通用範例；每一輪回答後換成依這一輪結果推導的下一步（`public/js/agent/next-steps.js`），最多 4 個，最後一個「其他問題」換回通用範例：
- 選公車：「到站前 3 分提醒我」（直接設定，已提醒就不再出現）、「開公車頁看動態」；行程：決策圖還沒有的狀態（「我很趕」「想省錢」「少走路」，點了在瀏覽器重算、不重問）、「回程怎麼走？」、「目的地天氣如何？」
- 股市：「看大盤」、「是○○嗎？」（名稱只部分相同時）、「那 0050 呢？」；發票：「存到我的發票」、「上一期中獎號碼」；天氣與空品互相延伸

**選公車就盯到站（L-14）**：決策選公車後，阿幫接著顯示那條路線的 `bus-route` 卡片，聚焦上車站（大字倒數、「你在這上車」），按「到站前 3／5 分提醒我」設定提醒（系統通知＋App 內 toast；這班已趕不上就提醒下一班），「開公車頁看動態」進公車頁看同一站、同一個提醒；手動進公車頁（帶 `?stop=`）也能設。提醒只在 App 開著時有效。

**股市（收盤行情）**：服務頁「股市」預設查上次查的股票（第一次是「台積電、0050」），卡片上方加權／櫃買指數，下面每檔收盤價與漲跌。**台股習慣漲紅、跌綠**（與其他卡片「綠＝好」相反，只用在股市），另有 ▲▼ 符號與 `aria-label`「上漲 5（0.23%）」，不只靠顏色。卡片內可再查別檔、按「也可能是」改選；固定附「收盤資料，不是即時報價；僅供參考，不構成投資建議」。問阿幫的互動（追問、卡片脈絡、問買賣）見 `AGENT.md` §5.1。

卡片規格與資料契約見 `CARDS.md`。即時欄位：倒數每秒遞減（本地計算），每 20–30 秒由 `host.callTool` 刷新。

**L2 確認視窗**（訂票、叫車）：顯示「車次／日期／起訖／張數」或「目的地」，按鈕「前往官方網站」；附一行「付款在官方網站完成，阿幫不會取得你的付款資料」。
