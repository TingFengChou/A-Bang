# UX 規格 — 阿幫・生活（交通）

版本：v0.4（2026-11-17）。參考原型：`docs/prototypes/transit-discussion.html`（瀏覽器直接開；4 個情境）；Agent 互動模型：`docs/prototypes/agent-interaction.html`（股市、發票掃描、選公車後盯到站＋提醒；右邊即時顯示事件流、模型看得到的歷史與卡片脈絡、命中的規則）。
正式實作在 `public/js/pages/agent.js`（✅ M5-08，`#/agent`）＋ `public/css/agent.css`，**由真實 NDJSON 事件驅動**（`AGENT.md` §3），原型中的假資料與 `sleep()` 只是示意。頭像：阿幫用吉祥物（`/brand/abang-think.svg`，與原型相同），每個小幫手是角色色彩圓形＋線條圖示（`public/js/icons.js`，與首頁格子同一套；`role=img`＋`aria-label` 念角色名）。

## 1. 原則

1. **淺色、簡單、手機優先**：不做深色 HUD；一屏只講一件事。
2. **看得到多 MCP 在合作**：阿幫點名工具、工具一句話回報（ADR-0009）。
3. **看得懂為什麼這樣建議**：決策圖把「資料＋你的狀態 → 建議」畫出來（ADR-0010）。
4. **誠實**：數字與發言來自真實資料；不加假延遲；估算一定標「估算」。
5. **可以行動**：結論卡片直接提供導航、訂票、叫車、提醒。
6. **可及**：`prefers-reduced-motion` 關閉動畫；色彩不是唯一資訊來源；觸控目標 ≥ 44px。

### 3.1 首頁與導覽：阿幫為中心（2026-11-21 重新設計）

Austin：「現在最下面都是公車相關（首頁／附近／公車／收藏），跟全方位資料整合與具備 edge AI 的 App 不太相符。」阿幫已經涵蓋交通、生活、消費、防詐，又有手機上的 AI；導覽要反映「什麼都可以問阿幫」，而不是公車 App。

**底部分頁列**（`public/js/tabs.js`，`<nav aria-label="主要分頁">`）：首頁｜服務｜**問阿幫（中央大鍵）**｜提醒｜我的。為什麼這樣分：
- **首頁**：每天打開先看的——問阿幫、現在的天氣空品與提醒、常用服務格子。
- **服務**：所有資料服務的目錄（原本占兩格的「附近」「公車」收進這裡），新服務加在這裡不必動分頁列。
- **問阿幫**放正中間、做成比分頁列高出一截的藍鵲圓盤：App 的核心是 agent，不是某一種資料。
- **提醒**：到站、下車、出門提醒原本散在公車頁與設定頁；提醒是阿幫「主動」的那一面，值得一格。有進行中的提醒時圖示上有數字（讀屏「提醒，2 個進行中」）。
- **我的**：存在這支手機的東西（收藏、常用地點、我的發票、提醒）、手機上的 AI、設定與隱私、關於與資料來源。不用登入，所以叫「我的」不叫「帳號」。
- 目前這一區：分頁本身 `aria-current="page"`，子頁（公車頁屬於服務、設定屬於我的、防詐頁屬於服務）`aria-current="true"`；圖示後面一塊淡色膠囊。每格觸控範圍 ≥ 44px。附近、公車搜尋、收藏不再是分頁，所以有返回鈕。舊網址（`#/nearby`、`#/bus`、`#/favs`、`#/settings`、`#/privacy`…）都照舊可用。
- **中央鍵與浮動阿幫**：中央鍵取代原本右下角的浮動阿幫（不兩個並存；同一個元素 `#abang-fab`，行為在 `abang-dock.js`）。在其他頁點了從下方拉出同一段對話（背後的頁面還在、知道你在哪一頁、「在這頁可以問」照舊）；在問阿幫頁它是目前這一頁，點了回到輸入框。有對話時圓盤右上青綠小點（讀屏「問阿幫（對話還在）」）；阿幫說了話你還沒看（提醒）時換成橘點並閃 3 下（「問阿幫（阿幫有話跟你說）」），打開對話或到問阿幫頁就清掉。提醒泡泡從中央鍵上方冒出、尾巴指向鍵（防詐頁也看得到，不再改用提示）。讀屏名稱都以看得到的「問阿幫」開頭。鍵盤打開時整條分頁列（含中央鍵、泡泡）收起，提醒改用提示。為什麼不是「點了就到 `#/agent` 整頁」：拉出面板不離開現在的頁面，看公車動態時問「那改坐捷運呢」不用來回切；整頁仍可從面板的「放大成整頁」或首頁輸入框進去。
- Android 返回鍵（`tabs.js` `backTarget`）：對話框或底部對話開著先收起；分頁本身（服務、提醒、我的、問阿幫）回首頁，不走分頁之間的歷史；只有在首頁才離開 App；其他頁有上一頁就回上一頁，沒有回首頁。
- 原生 App：分頁列底部留 `env(safe-area-inset-bottom)`（home indicator）；問阿幫頁輸入列底下多留 32px 給中央鍵，面板裡與鍵盤打開時不留。

**首頁**（`public/js/pages/home.js`、`public/js/home-now.js`），由上而下：
1. **手機上的 AI**（一條，點了到「我的」的說明）：照實說誰在判斷。手機 App 可用時「手機上的 AI・Gemini Nano（或 Apple Intelligence）—先在手機上聽懂你要做什麼，判斷留在手機」；關掉、不支援、模型下載中、網頁版都說「由阿幫伺服器判斷」，不誇大。
2. **主視覺**（綠色漸層＋3D 藍鵲）：「午安！我是阿幫」「有事問阿幫」「交通、生活、消費、防詐，一句話幫你查」；輸入框「想查什麼？」；範例問題各領域一句（去台北 101、會下雨嗎？、這期發票中了嗎？、這則簡訊是詐騙嗎？——防詐要貼訊息，開防詐頁）。
3. **現在**：天氣（氣溫＋降雨，`weather_now`）、空品（AQI＋等級，`aqi_nearby`）、最近一個提醒，三格點了到各自的頁面。用現有 `/api/v1/tools/:name`，不新增端點。已經允許定位才用你的位置；沒給過權限不在首頁跳權限框，用台北車站附近並寫明。先畫提醒那格與佔位，查到再補（不擋畫面）；查不到的那格不出現；離線寫「離線中」；天氣與空品都查到才記 10 分鐘（少一個下次重查），回首頁時上次的結果還有效就直接畫、不閃骨架；用台北車站查的結果在你允許定位後作廢。示範資料的天氣、空品標「示範」。到站、下車提醒每 20 秒送一次事件，內容沒變就不重畫（提醒頁同樣），鍵盤與讀屏的焦點不會掉。
4. 我的收藏（有才顯示，最多 3 個，站牌有最快一班）。
5. **防詐**：一張醒目的紅色大卡「收到可疑訊息？」，放在格子前面（不埋在最後）。
6. 交通、生活、消費與政府：一組一塊白底面板的格子（格子本身不再各自浮起），最下面「全部服務與說明 ›」。點格子圖示照舊飛進頁首（View Transitions），從頁首回到首頁或服務頁時飛回。

**服務**（`#/services`，`public/js/pages/services.js`）：防詐、交通、生活、消費與政府四組，每個服務一列：立體圖示＋名稱＋一句「在這裡可以做什麼」（沿用頁首說明，`registry.js` `descOf`）＋資料來源。

**提醒**（`#/reminders`，`public/js/pages/reminders.js`、清單整理 `public/js/reminder-items.js`）：進行中的下車提醒、到站提醒、出門提醒（依時間），每筆可取消（取消後焦點回到標題、提示「已取消提醒」）、公車的提醒有「看公車 ›」。通知權限被拒時照實說只在開著時提醒。下面「阿幫可以在這些時候叫你」教怎麼設（公車快到站、快到站該下車、該出門了）。原本設定頁的出門提醒清單搬到這裡（設定頁留一個連結）。

**我的**（`#/me`，`public/js/pages/me.js`）：「不用註冊、不用登入」；我存的（收藏、常用地點、我的發票、提醒，顯示數量）；手機上的 AI（狀態＋說明它做什麼、不做什麼＋到設定開關；首頁那條點進來會捲到這裡）；設定與隱私、隱私權政策、使用說明；關於與資料來源（165）。

英文外殼：分頁列 Home／Services／Ask Abang／Reminders／Me、新頁面標題（Services／Reminders／Me）、中央鍵讀屏名稱、提醒數字在 `shell-i18n.js`；頁面內文目前中文。

### 3.2 動態「下一句」建議（2026-11-21，產品負責人：「輸入 hint 都一樣，跟 Claude 引導用戶不一樣」）

輸入框的 placeholder、輸入框上方的建議（問阿幫頁與底部對話面板同一個）、首頁範例問題，都依情境猜「使用者接下來最可能問的話」，**阿幫有即時資料的排前面**。邏輯在 `public/js/agent/suggest.js`（AGENT.md §5.5）。
- **長什麼樣**：placeholder 是最可能的那一句（「例如：從台北101到西門町怎麼去？」），每輪回答後、換頁打開對話時更新。建議 chips：猜的問句在前（最多 3～4 句），動作（到站提醒、上車後提醒我下車、決策圖加狀態，最多 2 個）在後；**在公車／捷運頁、或這一輪剛查過公車到站時，提醒類動作（到站提醒、上車後提醒我下車、下車前提醒我）排第一**（產品負責人 2026-11-21 定案，`orderSuggest`），決策圖加狀態一律在問句後面；最後「其他問題／更多例子」列 profile 的固定範例。一開始（還沒問）沒有標題；回答後標「接下來可以」。點問句直接送出。
- **例子**：查完西門町→台北101（建議捷運）：「捷運現在多久一班？」「回程怎麼走？」（送「從台北101到西門町怎麼去？」）「台北101附近還有 YouBike 嗎？」；外面下雨：「下雨，少淋雨的走法」（送「下雨了，從西門町到台北101少走路怎麼去？」）排第一；深夜：「捷運幾點收班？」「附近的藥局有開嗎？」；早上平日有設定公司：「去公司怎麼走最快？」；從公車頁打開對話：「附近還有哪些公車？」「下車前提醒我」（上面仍有「在這頁可以問」）；英文那一輪只給英文句。
- **首頁範例**：交通、生活、消費各一句依時段與「現在」的天氣空品變（早上「捷運下一班幾分？」「出門要注意什麼？」；深夜「捷運幾點收班？」「明天會下雨嗎？」；下雨「明天還會下雨嗎？」），防詐固定「這則簡訊是詐騙嗎？」開防詐頁。天氣查到後才變的話淡入一次。
- **不閃爍、不打斷**：產生中保留舊的建議，好了再換（淡入 0.22 秒；reduced motion 不淡入）；內容一樣就不動畫面；用鍵盤停在建議上時，換完焦點留在建議群組的第一個（不掉回頁首）；按了「更多例子／其他問題」就留著固定範例，到下一輪或換頁才換回。
- **可及性**：建議列 `role="group"`、`aria-label`＝「建議問題／接下來可以」，畫面上的標題 `aria-hidden`（不重複唸）；不是即時區域（換建議不播報）；每個都是 `<button>`。
- **長對話（§4.17）**：建議列一律依**最新一輪**（展開舊的輪時不換）。點建議送出算不算「接著這一輪問」：程式為這一輪算的（「接下來可以」的問句、只剩一種方式時的換條件建議）、從這一輪結果推的規則句（回程、目的地附近 YouBike、下雨少淋雨…）、提到這一輪地名路線的猜句都算接著問（不分段）；依時段的一般建議、沒提到這一輪的猜句算新話題。點動作（到站提醒、開公車頁、加狀態）記成操作過這一輪（提醒頁連回當時的對話），提醒的確認句寫在那一輪裡。
- **送出時**：先拿掉跟剛送出那句相同的建議與綁上一輪的動作，其他的留到新的建議出來；送出中換頁、到站提醒變了都不換建議（答完再依新的一輪算）。
- **App 與網頁**：App 裡手機上的 AI 可用時由它猜（設定「用手機上的 AI 猜我接下來想問什麼」，預設開），網頁版、不可用、逾時或驗證後不足 3 句用規則；兩者看起來一樣（`data-src` 只給測試）。

## 4. 小幫手討論串

| 事件 | 呈現 | 時間 |
|---|---|---|
| `agent_note` | 阿幫頭像＋泡泡；`@角色` 以該角色色彩的 chip 顯示 | 打字指示 ≥ 300ms 後出現 |
| `tool_start` | 對應角色頭像出現「輸入中…」三點；右下小字 `tool 名稱 · MCP 來源` | 立即 |
| `tool_result.ok` | 「輸入中」換成 `speak` 一句話；右下加 `metrics`（例：`37 筆 · 快取`） | 與前一則間隔 ≥ 300ms（只為避免閃爍） |
| `tool_result` 失敗 | 灰色泡泡「這次沒查到（原因）」；不中斷其他工具 | — |
| `data_note` | 工具發言樣式：角色頭像（天氣、空品、路況）＋資料一句（「多雲 24°C，3 小時降雨 10%」「萬華測站 AQI 58（普通）」「國道 1號塞車，多 18 分」「這附近查不到天氣資料」）＋「→ 影響」（不用避雨／正在下雨：少走路、少騎車，室內方案加分／少待戶外：走路、騎車扣分／叫車、客運可能慢）；右下「行程比較用到的資料・示範資料」。排在行程結論前面；同一輪已有該角色發言時不重複 | 與前一則間隔 ≥ 300ms |
| `discussion_end` | 整串收合成一行：「小幫手討論完成・5 個工具・1 個 MCP」＋展開箭頭 | 收合動畫 250ms |

角色對照（`tool_start.role` → 名稱、色彩、圖示）：地點 place、天氣 place、公車 bus、YouBike bike、高鐵 rail、台鐵 tra、捷運 brand、路況 car、客運 car、票價 fare、叫車 car、訂票 rail。圖示為簡單線條 SVG（`public/ui/icons.js`），不要用表情符號。

## 5. 決策圖（`decision` 事件）

由左到右四欄：**資料**（工具）→ **你的狀態** → **方案** → **建議**。SVG，寬度自適應，高度依方案數（每方案 44px）。

動畫順序（總長約 2.4 秒；reduced-motion 時直接顯示最終狀態）：

| 步驟 | 內容 | 時長 |
|---|---|---|
| 1 | 資料欄：每個工具節點亮起，資料膠囊（小圓點）沿線流向「狀態」 | 600ms |

### 4.11 下車提醒（2026-11-21）

公車頁時間軸點站名就能設成上車站（站名虛線底線、整列寬的按鈕、`aria-pressed`；網址的 stop 與 dir 一起改；焦點移到上車站卡片；每 20 秒重畫焦點留在原處；上方提示「點站名設成上車站…」，選了之後改成「點其他站名可以改上車站」）。換上車站時原本的到站／下車提醒照舊，在上車站卡片上寫「另有提醒…」並可取消。選了上車站後，上車站卡片下方：「上車了嗎？要在哪一站下車？」下拉（只列上車站之後的站，值是站序，環狀路線同名站不會選錯；每 20 秒刷新不會重選）＋「快到時提醒我下車」。判斷「我這台」：沿站序從上車站往後第一個到站時間變小的站，就在剛離開上車站那台車的前方；目的站在它前方且中間沒有別台車＝目的站的下一班就是我這台，剩 ≤ 2 分提醒。設定時車正要進站（≤ 90 秒）＝等這台；看不出來時照站數 × 90 秒。進行中顯示「下車提醒：快到「X」時提醒你（約 N 分後到）」與「取消下車提醒」（不加 live role，避免每 20 秒重念）；沒有通知權限時寫明 App 關著不會提醒。快到時 toast「🔔 約 2 分後到「X」，準備下車」＋震動。App 設定當下就排好通知（第一次查失敗也會響），每次更新改時間；被系統關掉重開時，通知已響過就清掉不重響。`public/js/alight.js`。

### 4.12 定位失敗說原因（S1c，2026-11-21）

定位失敗分四種原因（`public/js/agent/client.js` `locationReason`：原生外掛錯誤碼 `OS-PLUG-GLOC-*`、網頁 `GeolocationPositionError`）：權限沒開（denied）、手機定位服務關閉（off）、太久沒回應（timeout）、其他（unavailable）。說明與按鈕在 `public/js/location-help.js`：
- 附近、生活服務頁：清單上方黃底說明「原因＋下一步＋現在先用台北車站附近」，按鈕「再試一次」；App 裡權限或定位服務關閉時多一個「到設定開啟」（專案內外掛 `AbangSystem`：Android 權限開 App 設定、定位服務開系統定位設定；iOS 只能開 App 設定），從設定回來自動再定位一次。
- 問阿幫：定位泡泡依原因說（「定位權限沒有打開；可以直接打地點，或到設定允許定位」），App 裡附「到設定開啟」。
- 設定頁：權限區定位「已拒絕」時（App）多「到設定開啟」；Android 拒絕過一次（`prompt-with-rationale`）顯示「拒絕過一次（下次用到會再問）」；畫面再出現時重新檢查。設成現在位置失敗時提示說原因。
- 首次使用引導：允許定位失敗時說原因。
- 網頁版沒有開設定的按鈕：說「到瀏覽器的網站設定，把『位置』改成允許」（安裝成 PWA 沒有網址列）。
- iOS 的定位服務總開關不在 App 設定頁：定位服務關閉時只說路徑「設定 → 隱私權與安全性 → 定位服務」，不給按鈕。打不開設定時說「打不開設定，請自己到手機的設定開啟」。

### 5.0.3 語音問阿幫（M14-01，2026-11-21，產品負責人：「讓阿幫聽得懂」、手機上優先）

把你說的話**在手機上**轉成文字，文字當作一般提問送出（跟打字一樣接上「阿幫在想」）；語音只在手機上轉成文字，不錄音、不上傳；**不退回系統或雲端辨識**（產品負責人 2026-11-21：「語言包要協助用戶裝，除非真的手機無法支援；不支援就反白，點擊後顯示原因」）。實作 `public/js/voice.js`（狀態機＋控制器＋辨識來源，與平台無關）、`public/js/voice-i18n.js`（中英字典）、`public/js/agent/voice-ui.js`（畫面）、原生外掛 `AbangVoice`（Android `AbangVoicePlugin.java`、iOS `AbangVoicePlugin.swift`）。
- **入口**：問阿幫輸入列的麥克風鍵（輸入框與「送出」之間，44×44，可及名稱「用說的問阿幫」；在聽時變成停止圖示、`aria-pressed="true"`、名稱「說完了，送出」）。底部對話面板是同一個畫面，所以也有。**長按中央「問阿幫」鍵**（0.45 秒）是捷徑：其他頁先拉出底部對話再開始聽，放開就送出；短按維持原本的行為（長按後的 click 不算）；鍵外圈亮琥珀色。長按對讀屏、鍵盤、切換控制不友善，所以只是捷徑，同樣的功能一定有麥克風鍵；中央鍵的讀屏名稱不變。
- **在聽面板**（輸入列上方）：左邊是思考動畫同一顆核心（Λ＋琥珀核心＋軌道），核心與光暈跟著音量放大（外掛的 level 事件 → CSS 變數 `--lv`，只動 transform／opacity）；右邊「在聽…」＋即時的辨識文字（還沒聽到字時是灰色提示「請說，例如：去台北 101 怎麼走」）＋怎麼結束（「說完停一下就會送出」／長按時「放開就送出」）＋「在手機上轉成文字，語音不離開手機」。按鈕：「取消」「說完了」（長按時不給「說完了」）。Esc 取消（不關掉底部對話）。
- **結束與送出**：停頓 1.5 秒（有聽到字之後才計時）、按「說完了」、放開中央鍵 → 等最後的文字（最多 3 秒，沒來就用已聽到的）→ 自動送出。長按時放開才結束：原生 `start` 帶 `hold`（iOS 不因停頓收尾；Android 停頓收尾拉長到 8 秒），辨識器仍提早給最後結果時，那一段先記著、接著聽，放開才把整句送出；一樣最多 30 秒（用說的那一句泡泡上有小麥克風）。開始 8 秒都沒聽到字 →「沒有聽到聲音」；一次最多 30 秒。換頁、收起底部對話、切到別的 App／鎖螢幕 → 取消，不在背後開著麥克風；原生端到背景、iOS 音訊被打斷（來電、耳機拔掉）也停止並送 error 事件，畫面不會卡在聽。第一次按麥克風跳權限框時 App 會暫時看不見，這時（準備聽）不取消，允許後就開始聽；原生 `start` 記號碼，等權限時被取消就不開麥克風。
- **語言**：最近一輪是英文（伺服器 status 事件的 `lang`）就用 en-US 辨識，面板也用英文；其他用 zh-TW。
- **錯誤**（外掛與網頁版共用的種類 `VOICE_ERRORS`，字典 `err.*`）：權限被拒 →「麥克風權限沒有打開。可以直接打字，或到設定允許麥克風。」＋「到設定開啟」（`AbangSystem.openSettings`）；沒聽到、沒聽清楚 →「再說一次」；已經聽到字才報「沒聽清楚」時直接送出聽到的。錯誤面板改暖色底。
- **讀屏**：只念「開始聽了，請說。」「取消了，沒有送出。」與錯誤（`role=status`）；辨識中的文字一直變，不念（`aria-hidden`），送出後對話紀錄（`role=log`）會念你說的話。
- **reduced motion／lite-motion**：核心不跟音量動、軌道不轉、面板不淡入，只有「在聽…」與辨識文字。
- **網頁版**：只在 Google Chrome 且 `SpeechRecognition.available({ langs, processLocally: true })` 回 `available` 時顯示麥克風，並設 `processLocally = true`（舊草案 `availableOnDevice`／`mode = 'ondevice-only'` 也支援）；屬性不存在就不開始。不能在本機辨識就不顯示，不把語音送到瀏覽器廠商的伺服器。只限 Google Chrome：無頭 Chromium 156 呼叫 `available()` 會讓整頁當掉（E2E 實測），其他 Chromium 系瀏覽器與 App 的 WebView 不確定。
- **手機 App**：只用手機上的辨識。Android：API 31+ 且 `isOnDeviceRecognitionAvailable` → `createOnDeviceSpeechRecognizer`；API 33+ 用 `checkRecognitionSupport` 看語言包（已安裝＝能用、pending＝下載中、supported＝可下載、都不是＝不支援這個語言）；API 31、32 查不到就先試，辨識器回語言不能用（錯誤 12、13）→ `language-missing`（說怎麼到設定下載＋「到手機設定下載」開 `ACTION_VOICE_INPUT_SETTINGS`）。iOS：`SFSpeechRecognizer`＋`AVAudioEngine`，`requiresOnDeviceRecognition = true`；`supportsOnDeviceRecognition` 為 false 就是不支援。SFSpeechRecognizer 沒有公開的下載語音資料 API（iOS 26 的 SpeechAnalyzer／AssetInventory 才有，另評估），所以 iPhone 只說怎麼開聽寫。權限第一次按麥克風才問（Android `RECORD_AUDIO`；iOS 麥克風＋語音辨識）。
- **麥克風的四種樣子**（`voice.js` `normalizeVoiceInfo` 的 state）：能用＝一般；語言包可下載＝一般（名稱「第一次要先下載中文語音包」），按了就請系統下載（產品負責人同意自動下載）：面板「正在下載中文語音包…70%」（Android 14+ 有進度；13 每 3 秒再問一次系統）、「先打字」可收起、下載中麥克風「準備中」（外圈轉、`aria-disabled`），好了「中文語音包好了，可以用說的了」＋「開始說」；排在 Wi-Fi、失敗、等超過 3 分鐘 → 說清楚＋「到手機設定下載」（Android）；回到 App 時重查。手機真的不支援（Android 12 以下、沒有手機上的辨識器、語言不支援；iPhone 不能在手機上辨識）＝**反白**（灰底虛線、`aria-disabled="true"` 但仍可按），按了面板說原因（例：「這支手機不支援在手機上辨識語音（需要 Android 12 以上，並安裝中文語音包）。可以直接打字。」；iPhone：「到「設定 → 一般 → 鍵盤」打開「啟用聽寫」，並在「聽寫語言」加入中文（台灣）…」），不開始聽、長按中央鍵也不聽。網頁版不能本機辨識＝不顯示（沒有語言包可裝，不必反白）。英文那一輪按麥克風時另外查 en-US 的語言包。
- **設定與隱私**：設定頁「語音」區塊「用語音問阿幫」開關（`localStorage abang.voice`，關掉就沒有麥克風鍵、長按中央鍵也不會聽）＋狀態（可以使用／第一次按會下載中文語音包／下載中／不能使用：原因）；權限區多「麥克風」一列（App）。隱私權政策第 3 節「語音問阿幫」：語音只在手機上轉成文字，不錄音、不上傳；語言包由手機系統下載；不支援就不提供。「阿幫的腦袋」（`#/ai`）「聽」卡片：手機上辨識（可用／可用：第一次按會下載語音包／語言包下載中／不支援：原因）、引擎、語言、麥克風權限；只顯示系統真的回報的。

### 5.0.4 阿幫會看（M14-02，2026-11-21，ADR-0015；產品負責人：「讓阿幫會看」）

拍可疑簡訊或選截圖查詐騙、拍站牌路牌問怎麼走、拍發票自動對獎。**手機上優先**：照片只在手機上讀字（Android ML Kit、iOS Vision），不上傳、不保存；讀出來的文字先給使用者看，**確認後才送**。實作 `public/js/vision.js`、`public/css/vision.css`、規則 `core/vision-text.js`、外掛 `AbangVision`。

**我的發票（本機，M10）**：服務頁「發票對獎」卡片下方。輸入 8 碼號碼＋消費日期 →「存起來，開獎自動對」，已開獎的期別立刻出結果，沒開獎的顯示「M/D 開獎」。號碼只存在手機（localStorage `invoices`，最多 100 張），對獎時經 `invoice_check_batch` 比對、伺服器不保存。**主動**：每次打開 App，開獎日已到的發票自動對獎，中獎時 toast（已允許通知時另發系統通知）、沒中時說「已對獎，這期沒中」；問阿幫查發票時提議存到「我的發票」。網頁沒有背景排程：App 沒打開就不會對，下次打開才對（不需推播伺服器、不保存使用者資料）。不串 Gmail、載具（需保存使用者帳號或憑證，屬 ADR 變更）。
**掃發票**：「掃發票 QR code」開相機視窗（`<dialog>`，`public/js/invoice-qr.js`），對準電子發票證明聯**左邊**的 QR code，一張接一張掃（同一張只存一次、存到時震動），按「完成」或 Esc 關閉並停相機，再一次對獎。掃到右邊明細 QR（`**` 開頭）提示改掃左邊；中間一維條碼只有期別也可以存。只取字軌號碼與開立日期，不保存統編、金額、品項；影像只在手機辨識不上傳。用瀏覽器內建 `BarcodeDetector`（Android Chrome、macOS Chrome 支援；iPhone Safari、Firefox 不支援 → 顯示「請手動輸入」，不加第三方掃碼套件）。相機需要安全連線（HTTPS 或 localhost）。

**接下來可以…（2026-11-20，使用者回饋；2026-11-21 起生活阿幫改成動態的「下一句」，§3.2，下面這些動作與問句仍是規則的一部分）**：一開始輸入框上方是通用範例；每一輪回答後換成依這一輪結果推導的下一步（`public/js/agent/next-steps.js`），最多 4 個，最後一個「其他問題」換回通用範例：

**股市（收盤行情）**：服務頁「股市」預設查上次查的股票（第一次是「台積電、0050」），卡片上方加權／櫃買指數，下面每檔收盤價與漲跌。**台股習慣漲紅、跌綠**（與其他卡片「綠＝好」相反，只用在股市），另有 ▲▼ 符號與 `aria-label`「上漲 5（0.23%）」，不只靠顏色。卡片內可再查別檔、按「也可能是」改選；固定附「收盤資料，不是即時報價；僅供參考，不構成投資建議」。問阿幫的互動（追問、卡片脈絡、問買賣）見 `AGENT.md` §5.1。

## 9. 3D（輕量）

- ✅ 原型已有：卡片立體進場（`translateZ`＋`rotateX` 8°）、排名翻轉。
- 限制：只用 CSS transform，不引入 WebGL；同時進行的 3D 動畫 ≤ 3 個；低階裝置（`navigator.hardwareConcurrency ≤ 4` 或 reduced-motion）降級為淡入。
- ✅ M5-11：問阿幫的結果卡片與決策圖以 `.enter3d` 立體進場（`rotateX(8deg)`＋`translateZ`，依序延遲）；決策圖重算時位置改變的方案以 FLIP（Web Animations）滑到新位置，同時最多 3 個；`html.lite-motion`（`hardwareConcurrency ≤ 4` 或 reduced motion）只淡入、不翻轉。
- ✅ 2026-11-20 交通方式一律用圖示＋動畫（使用者：「公車、步行…都要用 icon，之前都有圖示加動畫，3D 更好」）：`public/ui/cards/mode-icons.js` 一套線條圖示（步行、YouBike、公車、捷運、高鐵、台鐵、客運、叫車＋地點、天氣、空品、路況、票價、行程）與**立體代幣** `token()`（漸層＋上緣高光＋厚度陰影＋微透視 `rotateX 14°／rotateY -10°`；`.go` 輕輕浮動）。用在：行程卡（方案代幣、分段條每段圖示＋分鐘、分段依序長出、一顆小代幣沿路線跑一趟、分段明細）、決策圖（資料來源與方案節點都有圖示、勝出節點厚度陰影、建議節點呼吸光暈、勝出路徑虛線流動）、公車卡片與公車頁（車的位置是浮動的公車代幣、上車站脈衝光圈、上車站大倒數旁的公車代幣）。全部只用 CSS；reduced motion 與 `html.lite-motion` 不動。
