# UX 規格 — 阿幫・生活（交通）

版本：v0.4（2026-11-17）。參考原型：`docs/prototypes/transit-discussion.html`（瀏覽器直接開；4 個情境）。
正式實作在 `public/js/pages/agent.js`（✅ M5-08，`#/agent`）＋ `public/css/agent.css`，**由真實 NDJSON 事件驅動**（`AGENT.md` §3），原型中的假資料與 `sleep()` 只是示意。頭像目前以角色名縮寫＋色彩圓形呈現（線條 SVG 圖示待補）。

## 1. 原則

1. **淺色、簡單、手機優先**：不做深色 HUD；一屏只講一件事。
2. **看得到多 MCP 在合作**：阿幫點名工具、工具一句話回報（ADR-0009）。
3. **看得懂為什麼這樣建議**：決策圖把「資料＋你的狀態 → 建議」畫出來（ADR-0010）。
4. **誠實**：數字與發言來自真實資料；不加假延遲；估算一定標「估算」。
5. **可以行動**：結論卡片直接提供導航、訂票、叫車、提醒。
6. **可及**：`prefers-reduced-motion` 關閉動畫；色彩不是唯一資訊來源；觸控目標 ≥ 44px。

## 4. 小幫手討論串

| 事件 | 呈現 | 時間 |
|---|---|---|
| `agent_note` | 阿幫頭像＋泡泡；`@角色` 以該角色色彩的 chip 顯示 | 打字指示 ≥ 300ms 後出現 |
| `tool_start` | 對應角色頭像出現「輸入中…」三點；右下小字 `tool 名稱 · MCP 來源` | 立即 |
| `tool_result.ok` | 「輸入中」換成 `speak` 一句話；右下加 `metrics`（例：`37 筆 · 快取`） | 與前一則間隔 ≥ 300ms（只為避免閃爍） |
| `tool_result` 失敗 | 灰色泡泡「這次沒查到（原因）」；不中斷其他工具 | — |
| `discussion_end` | 整串收合成一行：「小幫手討論完成・5 個工具・1 個 MCP」＋展開箭頭 | 收合動畫 250ms |

角色對照（`tool_start.role` → 名稱、色彩、圖示）：地點 place、天氣 place、公車 bus、YouBike bike、高鐵 rail、台鐵 tra、捷運 brand、路況 car、客運 car、票價 fare、叫車 car、訂票 rail。圖示為簡單線條 SVG（`public/ui/icons.js`），不要用表情符號。

## 5. 決策圖（`decision` 事件）

由左到右四欄：**資料**（工具）→ **你的狀態** → **方案** → **建議**。SVG，寬度自適應，高度依方案數（每方案 44px）。

動畫順序（總長約 2.4 秒；reduced-motion 時直接顯示最終狀態）：

| 步驟 | 內容 | 時長 |
|---|---|---|
| 1 | 資料欄：每個工具節點亮起，資料膠囊（小圓點）沿線流向「狀態」 | 600ms |
| 2 | 狀態欄：每個狀態標籤淡入；自動判斷的狀態以虛線連回產生它的工具（`CRIT_SRC` 對應：戶外 ← 天氣（空品不佳且沒下雨時 ← 空品）、塞車風險 ← 路況、費用 ← 票價；空品不佳 ← 空品） | 400ms |
| 3 | 方案欄：方案依分數由高到低翻轉排序（FLIP，`rotateX`）；連線粗細 = 分數 | 600ms |
| 4 | 被硬限制排除的方案：灰階、刪除線、標註「會遲到」 | 200ms |
| 5 | 勝出路徑（勝出方案 ← 關鍵比較項目 ← 資料來源）亮起，其他淡出到 30% | 400ms |
| 6 | 「為什麼」一句話（`decision.reason`）出現 | 200ms |

**狀態 chips**（決策圖上方）：

- 自動判斷：`自動：下雨`（來源工具的色彩點＋可點 ✕ 關閉）
- 你說的：`你說的：帶行李`
- 你選的：可加選 chips（趕時間、想省錢、少走路、帶行李）
- 點任何 chip → 前端以同一份 `decide.js`（`/core/decide.js` 以 ES module 提供給瀏覽器）立即重算，重播步驟 3–6；不呼叫伺服器。
- 關掉某個自動狀態時，理由句改為「不考慮『下雨』的話，…」。

**明細**：每個方案可展開長條圖（各比較項目得分 × 權重），標示最影響結果的兩項。

✅ M5-09：`public/ui/agent/decision-graph.js`（`renderDecision(root, decision, { sources, decide, CRITERIA })`，SVG 以 DOM API 建立、含 `<title>`／`<desc>` 文字替代）；伺服器以白名單提供 `/core/decide.js`；`plan_trip` 輸出與 `decision` 事件帶 `arriveBy`／`arriveByMin` 讓前端重算與伺服器一致（`test/agent-events.test.js` 驗證）。動畫為 CSS 分段淡入（步驟 1–6），排名翻轉（FLIP）與 3D 留待 M5-11。

## 6. 結論卡片

| 情境 | 卡片 | 主要內容 | 行動按鈕 |
|---|---|---|---|
| 從 A 到 B | `trip` | 建議方案名稱、總時間、費用、抵達時間；分段時間條（走路／等車／乘車，依 mode 上色）；備案 2 個 | 導航（第一段起點）、提醒我出門、備案、叫車（若有）、訂票（若含軌道） |
| 公車路線 | `bus-route` | 方向切換、站序時間軸、即將到站高亮、車牌 | 導航到最近站、提醒我 |
| 附近站牌／YouBike | `nearby`／`youbike` | 依距離排序、可借／可還、即時更新時間 | 導航 |
| 高鐵／台鐵 | `timetable` | 車次、出發、抵達、行車時間；被排除的班次灰階 | 訂票（L2，先確認視窗）、加入行事曆 |
| 捷運 | `metro` | 月台、目的地、到站分鐘 | 導航到站 |

卡片規格與資料契約見 `CARDS.md`。即時欄位：倒數每秒遞減（本地計算），每 20–30 秒由 `host.callTool` 刷新。

**L2 確認視窗**（訂票、叫車）：顯示「車次／日期／起訖／張數」或「目的地」，按鈕「前往官方網站」；附一行「付款在官方網站完成，阿幫不會取得你的付款資料」。

## 8. 文案

- 阿幫：口語、先講結論、偶爾「報你知」；不用驚嘆號連發、不用表情符號。
- 工具：第一人稱、一句話、含一個關鍵數字（「西門站還有 8 台，騎過去約 25 分。」）。
- 理由句：「選『X』：因為{狀態}，{前兩個優勢}，{排除說明}。」（`decide.js` 產生）
- 估算值前面加「約」，並在卡片標註「估算」。
- 錯誤：說明發生什麼＋下一步（「公車資料暫時連不上，先給你 YouBike 的選擇。」）。

## 9. 3D（輕量）

- ✅ 原型已有：卡片立體進場（`translateZ`＋`rotateX` 8°）、排名翻轉。
- 限制：只用 CSS transform，不引入 WebGL；同時進行的 3D 動畫 ≤ 3 個；低階裝置（`navigator.hardwareConcurrency ≤ 4` 或 reduced-motion）降級為淡入。
- ✅ M5-11：問阿幫的結果卡片與決策圖以 `.enter3d` 立體進場（`rotateX(8deg)`＋`translateZ`，依序延遲）；決策圖重算時位置改變的方案以 FLIP（Web Animations）滑到新位置，同時最多 3 個；`html.lite-motion`（`hardwareConcurrency ≤ 4` 或 reduced motion）只淡入、不翻轉。
- 🔭 評估：3D 吉祥物（靜態渲染圖）、3D 傾斜路線地圖。

## 10. 可及性

- 討論串容器 `role="log" aria-live="polite"`；結論卡片出現時朗讀建議與理由。
- 決策圖提供文字替代（`<desc>` 與可展開的表格）。
- 所有按鈕可鍵盤操作；焦點樣式清楚；對比 ≥ 4.5:1（`test/a11y.test.js` 檢查淺色、深色主題與卡片色彩）。
- ✅ M6-04：第一個 Tab 是「跳到主要內容」（hash 路由，用按鈕把焦點移到 `main`）；分頁列目前頁 `aria-current="page"`；toast `role="status"`。
- ✅ M6-04 播報到站：卡片外框有常駐的 `aria-live="polite"` 區塊（`.ab-sr`），刷新後播報句有變才念（卡片的 `announce()`：公車路線＝點開的站或即將進站的站、站牌＝最快 3 班、捷運＝最近 2 班）；PWA 公車路線與站牌頁同樣做法（`announcer()`）。第一次載入不念（內容本身會被讀到）。
