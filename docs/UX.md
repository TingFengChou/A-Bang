# UX 規格 — 阿幫・生活（交通）

版本：v0.4（2026-11-17）。參考原型：`docs/prototypes/transit-discussion.html`（瀏覽器直接開；4 個情境）；Agent 互動模型：`docs/prototypes/agent-interaction.html`（股市、發票掃描、選公車後盯到站＋提醒；右邊即時顯示事件流、模型看得到的歷史與卡片脈絡、命中的規則）。
正式實作在 `public/js/pages/agent.js`（✅ M5-08，`#/agent`）＋ `public/css/agent.css`，**由真實 NDJSON 事件驅動**（`AGENT.md` §3），原型中的假資料與 `sleep()` 只是示意。頭像：阿幫用吉祥物（`/brand/abang-think.svg`，與原型相同），每個小幫手是角色色彩圓形＋線條圖示（`public/js/icons.js`，與首頁格子同一套；`role=img`＋`aria-label` 念角色名）。

## 1. 原則

1. **淺色、簡單、手機優先**：不做深色 HUD；一屏只講一件事。
2. **看得到多 MCP 在合作**：阿幫點名工具、工具一句話回報（ADR-0009）。
3. **看得懂為什麼這樣建議**：決策圖把「資料＋你的狀態 → 建議」畫出來（ADR-0010）。
4. **誠實**：數字與發言來自真實資料；不加假延遲；估算一定標「估算」。
5. **可以行動**：結論卡片直接提供導航、訂票、叫車、提醒。
6. **可及**：`prefers-reduced-motion` 關閉動畫；色彩不是唯一資訊來源；觸控目標 ≥ 44px。

## 4. 小幫手討論串

| 事件 | 呈現 | 時間 |
|---|---|---|
| `agent_note` | 阿幫頭像＋泡泡；`@角色` 以該角色色彩的 chip 顯示 | 打字指示 ≥ 300ms 後出現 |
| `tool_start` | 對應角色頭像出現「輸入中…」三點；右下小字 `tool 名稱 · MCP 來源` | 立即 |
| `tool_result.ok` | 「輸入中」換成 `speak` 一句話；右下加 `metrics`（例：`37 筆 · 快取`） | 與前一則間隔 ≥ 300ms（只為避免閃爍） |
| `tool_result` 失敗 | 灰色泡泡「這次沒查到（原因）」；不中斷其他工具 | — |
| `discussion_end` | 整串收合成一行：「小幫手討論完成・5 個工具・1 個 MCP」＋展開箭頭 | 收合動畫 250ms |

角色對照（`tool_start.role` → 名稱、色彩、圖示）：地點 place、天氣 place、公車 bus、YouBike bike、高鐵 rail、台鐵 tra、捷運 brand、路況 car、客運 car、票價 fare、叫車 car、訂票 rail。圖示為簡單線條 SVG（`public/ui/icons.js`），不要用表情符號。

## 5. 決策圖（`decision` 事件）

由左到右四欄：**資料**（工具）→ **你的狀態** → **方案** → **建議**。SVG，寬度自適應，高度依方案數（每方案 44px）。

動畫順序（總長約 2.4 秒；reduced-motion 時直接顯示最終狀態）：

| 步驟 | 內容 | 時長 |
|---|---|---|
| 1 | 資料欄：每個工具節點亮起，資料膠囊（小圓點）沿線流向「狀態」 | 600ms |
| 2 | 狀態欄：每個狀態標籤淡入；自動判斷的狀態以虛線連回產生它的工具（`CRIT_SRC` 對應：戶外 ← 天氣（空品不佳且沒下雨時 ← 空品）、塞車風險 ← 路況、費用 ← 票價；空品不佳 ← 空品） | 400ms |
| 3 | 方案欄：方案依分數由高到低翻轉排序（FLIP，`rotateX`）；連線粗細 = 分數 | 600ms |
| 4 | 被硬限制排除的方案：灰階、刪除線、標註「會遲到」 | 200ms |
| 5 | 勝出路徑（勝出方案 ← 關鍵比較項目 ← 資料來源）亮起，其他淡出到 30% | 400ms |
| 6 | 「為什麼」一句話（`decision.reason`）出現 | 200ms |

**狀態 chips**（決策圖上方）：

- 自動判斷：`自動：下雨`（來源工具的色彩點＋可點 ✕ 關閉）
- 你說的：`你說的：帶行李`
- 你選的：可加選 chips（趕時間、想省錢、少走路、帶行李）
- 點任何 chip → 前端以同一份 `decide.js`（`/core/decide.js` 以 ES module 提供給瀏覽器）立即重算，重播步驟 3–6；不呼叫伺服器。
- 關掉某個自動狀態時，理由句改為「不考慮『下雨』的話，…」。

**明細**：每個方案可展開長條圖（各比較項目得分 × 權重），標示最影響結果的兩項。

✅ M5-09：`public/ui/agent/decision-graph.js`（`renderDecision(root, decision, { sources, decide, CRITERIA })`，SVG 以 DOM API 建立、含 `<title>`／`<desc>` 文字替代）；伺服器以白名單提供 `/core/decide.js`；`plan_trip` 輸出與 `decision` 事件帶 `arriveBy`／`arriveByMin` 讓前端重算與伺服器一致（`test/agent-events.test.js` 驗證）。動畫為 CSS 分段淡入（步驟 1–6），排名翻轉（FLIP）與 3D 留待 M5-11。

### 5.0 設定與隱私（M11-04，2026-11-21）

首頁底部「設定與隱私」→ `#/settings`：裝置端 AI 開關（網頁版停用）與狀態、常用地點（家／公司／學校：「設成現在位置」；已設定時降為次要按鈕「重設」並先確認；「清除」要確認；定位中按鈕顯示「定位中…」；只顯示已設定／還沒設定，不顯示座標；更新時不重建列，焦點留在原處）、定位與通知權限狀態（改權限到手機設定）、本機資料清單與清除（要確認）、連到 `#/privacy` 隱私權政策（實際做法：不收集可識別個人的資料、問題與位置只用來回答、本機通知、本機資料）。啟動畫面：淺色底＋藍鵲＋Abang（`node scripts/build-icons.js` 產生）。

### 5.1 接著改、排除與不適合（2026-11-21）

- 接著改的那一輪，討論串第一句由程式產生：「沿用：西門町 → 台北101｜改：不要叫車」（只改使用者提到的部分）。
- 決策圖被排除的方案三種標籤：**遲到**（紅色，超過抵達時間）、**不要**（灰色、不劃線，使用者說不要）、**不適合**（淺橘虛線框，阿幫依狀態判斷，例：帶長輩不建議騎 YouBike）；讀屏念「叫車，已排除：你說不要叫車」。
- 帶長輩、小孩、行動不便時第一句先說「我會避開 YouBike」；使用者明講要騎時照他選並提醒注意安全。
- 定位泡泡：「定位中…」→「拿到了，用你現在的位置」／「沒拿到你的位置；可以直接打地點，或到手機設定打開定位」。
- 手機鍵盤打開時收起底部分頁列（`html.kb-open`）。
- 模式說明：App 在手機上判斷時加一句「阿幫先在手機上用 Gemini Nano／Apple Intelligence 聽懂你要做什麼」（aria-live）。
- 「重來」：`context_reset` 事件 → 「重新開始」分隔線、前面的對話變淡（不清空，回得去看）。
- 接著問的那一輪，天氣、空品跟上一輪一樣時收合成「天氣同上（…）」（`details`，點開看完整卡片）。
- 決策圖畫出沒列入比較的方式（`decision.skipped`）：「收班」「沒列入」灰色節點，讀屏念原因。
- 待做：出門建議小卡（傘、衣著、口罩）。

## 6. 結論卡片

| 情境 | 卡片 | 主要內容 | 行動按鈕 |
|---|---|---|---|
| 從 A 到 B | `trip` | 建議方案名稱、總時間、費用、抵達時間；分段時間條（走路／等車／乘車，依 mode 上色）；備案 2 個 | 導航（第一段起點）、提醒我出門、備案、叫車（若有）、訂票（若含軌道） |
| 公車路線 | `bus-route` | 方向切換、站序時間軸、即將到站高亮、車牌 | 導航到最近站、提醒我 |
| 附近站牌／YouBike | `nearby`／`youbike` | 依距離排序、可借／可還、即時更新時間 | 導航 |
| 高鐵／台鐵 | `timetable` | 車次、出發、抵達、行車時間；被排除的班次灰階 | 訂票（L2，先確認視窗）、加入行事曆 |
| 捷運 | `metro` | 月台、目的地、到站分鐘 | 導航到站 |

**我的發票（本機，M10）**：服務頁「發票對獎」卡片下方。輸入 8 碼號碼＋消費日期 →「存起來，開獎自動對」，已開獎的期別立刻出結果，沒開獎的顯示「M/D 開獎」。號碼只存在手機（localStorage `invoices`，最多 100 張），對獎時經 `invoice_check_batch` 比對、伺服器不保存。**主動**：每次打開 App，開獎日已到的發票自動對獎，中獎時 toast（已允許通知時另發系統通知）、沒中時說「已對獎，這期沒中」；問阿幫查發票時提議存到「我的發票」。網頁沒有背景排程：App 沒打開就不會對，下次打開才對（不需推播伺服器、不保存使用者資料）。不串 Gmail、載具（需保存使用者帳號或憑證，屬 ADR 變更）。
**掃發票**：「掃發票 QR code」開相機視窗（`<dialog>`，`public/js/invoice-qr.js`），對準電子發票證明聯**左邊**的 QR code，一張接一張掃（同一張只存一次、存到時震動），按「完成」或 Esc 關閉並停相機，再一次對獎。掃到右邊明細 QR（`**` 開頭）提示改掃左邊；中間一維條碼只有期別也可以存。只取字軌號碼與開立日期，不保存統編、金額、品項；影像只在手機辨識不上傳。用瀏覽器內建 `BarcodeDetector`（Android Chrome、macOS Chrome 支援；iPhone Safari、Firefox 不支援 → 顯示「請手動輸入」，不加第三方掃碼套件）。相機需要安全連線（HTTPS 或 localhost）。

**接下來可以…（2026-11-20，使用者回饋）**：一開始輸入框上方是通用範例；每一輪回答後換成依這一輪結果推導的下一步（`public/js/agent/next-steps.js`），最多 4 個，最後一個「其他問題」換回通用範例：
- 選公車：「到站前 3 分提醒我」（直接設定，已提醒就不再出現）、「開公車頁看動態」；行程：決策圖還沒有的狀態（「我很趕」「想省錢」「少走路」，點了在瀏覽器重算、不重問）、「回程怎麼走？」、「目的地天氣如何？」
- 股市：「看大盤」、「是○○嗎？」（名稱只部分相同時）、「那 0050 呢？」；發票：「存到我的發票」、「上一期中獎號碼」；天氣與空品互相延伸

**選公車就盯到站（L-14）**：決策選公車後，阿幫接著顯示那條路線的 `bus-route` 卡片，聚焦上車站（大字倒數、「你在這上車」），按「到站前 3／5 分提醒我」設定提醒（系統通知＋App 內 toast；這班已趕不上就提醒下一班），「開公車頁看動態」進公車頁看同一站、同一個提醒；手動進公車頁（帶 `?stop=`）也能設。提醒只在 App 開著時有效。

**股市（收盤行情）**：服務頁「股市」預設查上次查的股票（第一次是「台積電、0050」），卡片上方加權／櫃買指數，下面每檔收盤價與漲跌。**台股習慣漲紅、跌綠**（與其他卡片「綠＝好」相反，只用在股市），另有 ▲▼ 符號與 `aria-label`「上漲 5（0.23%）」，不只靠顏色。卡片內可再查別檔、按「也可能是」改選；固定附「收盤資料，不是即時報價；僅供參考，不構成投資建議」。問阿幫的互動（追問、卡片脈絡、問買賣）見 `AGENT.md` §5.1。

卡片規格與資料契約見 `CARDS.md`。即時欄位：倒數每秒遞減（本地計算），每 20–30 秒由 `host.callTool` 刷新。

**L2 確認視窗**（訂票、叫車）：顯示「車次／日期／起訖／張數」或「目的地」，按鈕「前往官方網站」；附一行「付款在官方網站完成，阿幫不會取得你的付款資料」。

## 8. 文案

- 阿幫：口語、先講結論、偶爾「報你知」；不用驚嘆號連發、不用表情符號。
- 工具：第一人稱、一句話、含一個關鍵數字（「西門站還有 8 台，騎過去約 25 分。」）。
- 理由句：「選『X』：因為{狀態}，{前兩個優勢}，{排除說明}。」（`decide.js` 產生）
- 估算值前面加「約」，並在卡片標註「估算」。
- 錯誤：說明發生什麼＋下一步（「公車資料暫時連不上，先給你 YouBike 的選擇。」）。

## 9. 3D（輕量）

- ✅ 原型已有：卡片立體進場（`translateZ`＋`rotateX` 8°）、排名翻轉。
